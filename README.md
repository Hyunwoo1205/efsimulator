# efsimulator

현재 상점에서 이용 가능한 eFootball 선수 상품과 그 카드의 이름·이미지·표시 OVR, 판매기간/현재상태를 검색하고 갱신하는 한국어 사이트를 개발합니다. 장기 목표는 선수팩 개봉 시뮬레이터이며, 먼저 출처 조사, 데이터베이스, 검색 사이트와 지속 갱신을 완성합니다. 상품별 감독 관계를 일괄 반환하는 정상 API가 미확보이므로 감독은 현재 모든 상품과 독립 감독 화면의 서비스 지원 범위에서 제외합니다.

최신 단계·이전 결과·현재 작업·다음 작업과 미해결 조건은 아래 로드맵과 작업 계획을 기준으로 확인합니다. 관리 도구의 검증 성공을 제품 구현 완료로 해석하지 않습니다.

## 개발 진행 기준

- [로드맵](docs/ROADMAP.md): R0~R6 단계, 완료 조건과 현재·이전·다음 작업.
- [작업 계획과 이력](docs/WORKPLAN.md): 현재 작업의 순서·검증·추가 조건과 파일 최신화 검토 결과.
- [파일 최신화 목록](docs/FILE_SYNC.json): 관리 파일의 역할·우선순위·연관 관계·갱신 조건.
- [작업 지침](AGENTS.md): 작업 시작부터 완료까지 지켜야 할 문서·파일 최신화 절차.

작업마다 위 문서를 확인하고, 파일을 추가·삭제·이름 변경할 때 최신화 목록도 같은 변경에서 갱신합니다. 영향받는 파일은 우선순위와 의존 순서에 따라 수정하거나 변경이 필요 없는 근거를 기록합니다.

## 개발 환경과 검사

기준 도구는 Node.js `24.19.0`, npm `11.9.0`입니다. 준비된 클라우드 환경에서는 다음과 같이 활성화합니다.

```bash
source /workspace/efsimulator-environment/activate.sh
cd /workspace/efsimulator
npm ci --ignore-scripts --no-audit --no-fund
npm run project:check
npm test
npm run build
npm run preview -- --port 4173
```

미리보기는 `http://127.0.0.1:4173`에서 열 수 있습니다. `npm run dev`는 빌드 후 미리보기를 시작합니다. `npm run data:prepare`는 저장한 조사 근거에서 표본을 재현하는 명령이며 인터넷에서 새 자료를 수집하지 않습니다.

`npm run build`는 현재 입력을 검증해 SQLite와 정적 사이트를 생성합니다. 최신 확보 수량·출처 총계·미확인 범위는 `data/catalog.seed.json`의 `coverage`와 작업 계획에서 확인합니다. 상품별 가격·조건과 전체 구성은 확인한 범위만 표시합니다. 출처 목록의 카드 수는 실존 선수 수가 아니며, 확인한 카드 구성만으로 상품 전체 구성 완료를 뜻하지 않습니다. 전체 출처 수집이나 자동 갱신이 완료된 상태도 아닙니다.

전체 카드 API 감사는 실제 `https://efhub.com/api/public/players?page=1&limit=100` 요청의 HTTP 403에서 중단됐습니다. 이번 감사에서 확보한 페이지는 0개이고 `complete: false`이며, 이전 전수 검증은 미완료 이력입니다. 최신 현행 상품 범위에서는 전역 전수 감사를 공개의 무조건 선행 조건으로 두지 않습니다. 이는 관측한 쿼리의 응답이며 모든 API 경로 차단이나 도구 자체의 한계로 단정하지 않습니다. 자세한 실행 결과는 [API 감사 기록](data/research/card-api-audit.json)을 참조합니다.

기존 Pages의 루트 정적 배포와 호환할 공개 파일은 새 빌드 후 아래 명령으로 생성하고 확인합니다.

```bash
npm run pages:export
npm run pages:check
```

루트의 HTML·JS·CSS·데이터 등 고정 공개 파일 7개는 추적 생성물입니다. `web/*`와 seed를 수정한 뒤 다시 빌드·내보내고 루트 사본은 직접 수정하지 않습니다. CI는 새 빌드 후 바이트 일치 검사만 수행하며 불일치를 자동 갱신으로 숨기지 않습니다. 이 호환 구성의 준비와 실제 대시보드 설정 확인·공개 배포 검증은 구분합니다. 자세한 대상과 향후 `dist` 직접 배포 전환은 배포 절차를 따릅니다.

Python Playwright와 Chromium이 설치된 환경에서는 미리보기 실행 후 `npm run test:browser`로 실제 표본의 탐색·오류·반응형 화면을 검사합니다. 이 도구는 사이트 빌드의 의존성이 아닙니다. `npm run project:check -- --base <기준 커밋>`은 파일 정합성과 함께 이번 변경의 검토 기록까지 검사합니다.

데이터 구조와 갱신 보호는 [초기 구조](docs/ARCHITECTURE.md), 출처별 조사 이력은 [초기 조사](docs/sources/INITIAL_RESEARCH.md)·[후속 조사](docs/sources/FOLLOWUP_RESEARCH.md), 실제 배포 전환은 [배포 절차](docs/DEPLOYMENT.md)를 참조합니다. [Mourinho 개별 조사 원본](docs/sources/MOURINHO_PRODUCT_RESEARCH.md)은 비활성 연구 이력으로만 보존하며 서비스 데이터로 채택하지 않습니다. 실행 결과와 최신 서비스 범위는 작업 계획에 기록합니다.

## 제품 및 운영 기준

- 현행 상품과 그 카드·판매 시작/종료/상태·갱신에 집중합니다. 과거 전체·전역 카드·다른 버전 신규 확보는 보류하고 기존 데이터/버전 탐색은 보존합니다. 부분 공개와 대상 범위 완료를 구분합니다.
- [현행 상품 대조](docs/sources/CURRENT_SHOP_COVERAGE.md)는 공식 모수·지역/플랫폼·상품 대응·소개/전체 구성을 구분합니다. 전역카탈로그 총계나 최신 일부만으로 현재 상점 전체를 확보했다고 표시하지 않습니다. 확정된 현행 구성의 누락/중복·필수 필드는 검증합니다.
- 공식 eFootball·EFHub에서 실제 제공하는 카드·상품 데이터의 식별자와 관계, 필드별 출처·관찰 시점, 가격·재화·조건과 변경 이력을 보존합니다.
- 감독은 상품별 관계를 일괄 반환하는 정상 API가 확보되기 전까지 모든 상품에서 지원 범위에서 제외합니다. 일반 감독 목록은 관계 API가 아니며, 개별 기사·스크린샷·상품별 일대일 조사와 추가 감독 수집을 중단합니다. 이전 수동 Mourinho 사례와 Niko 표본은 활성 목록·상세·상품 구성에 사용하지 않고 연구 원본만 보존합니다. 이 범위 제외를 실제 감독 없음이나 전체 구성 완료로 표시하지 않습니다.
- 공개 주소는 [efsimulator.pages.dev](https://efsimulator.pages.dev)입니다. 주소 연결과 앱 배포 완료는 별개이며, 공개 동작은 구현·배포 후 검증합니다.
- Cloudflare Pages 무료 구성을 먼저 검토합니다. 서버·API가 필요하면 무료 웹/API 호스팅을 검토하고, 차선으로 OCI A1 Flex 2 OCPU·12GB ARM64 구성을 평가합니다. 추가 비용이 드는 구성을 기본값으로 두지 않습니다.
- 일괄 구매·일괄 지급 유형의 팩은 코인 결제 여부와 관계없이 DB·검색에 포함하고 미래 개봉 시뮬레이터에서는 제외합니다. API의 `/packs` 경로가 곧 이 상품 유형을 뜻하지는 않습니다. 시뮬레이터의 추첨 방식·연출·구현은 계속 보류하며, 기반 완료 후 코인 기반 특수 선수 명단만을 대상으로 별도 계획을 세웁니다.

`data/catalog.seed.json`은 누적 카탈로그입니다. 최신 수집 창에서 사라진 이전 상품·카드는 삭제하지 않으며, 기존 DB 없는 CI도 추적 seed를 기준으로 병합합니다. 원본 관측이나 seed를 지우고 현재 창만으로 재초기화하지 않습니다. 실제 삭제·범위 변경은 이력을 보존하는 별도 검토로 처리합니다.

이름/이미지/OVR 외 안정ID·타입·상품 연결은 같은 카드/구성을 식별하고, 기간/지역/확인 시각은 현재 상점을 판정하며, 확인된 가격/재화/규칙은 향후 정확한 비용/추첨을 위해 필요합니다. 미확인은null로 남깁니다. 누적 보존과 현행 판매 뷰는 구분하며 기존9상품을 판매 중으로 자동 승격하지 않습니다.
