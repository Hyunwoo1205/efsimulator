# API 후보 검증과 선정 계획

이 문서는 **R1/T008 계획 재작성**의 산출물이며 다음 실행은 **R1/T009 후보 검증**이다. 실제 이전/현재/다음 상태는 [WORKPLAN](WORKPLAN.md)을 따른다. 이 문서는 계획이며 새 수집·공급자 연락·계약·DB 구축을 실행한 결과가 아니다.

**최종 선정은 보류한다. 현재 모든 필수 게이트를 통과한 카드 공급자는 없다.** 한국 공식 확률표를 대상 기준으로 사용하고, EFHub는 상품 관계·이미지의 우선 검증 후보, PesLig는 카드 필드 보강 후보로 둔다. 후보 조합도 각 공급자의 권리와 상품/회차 매핑이 모두 확인되어야 한다.

## 대상과 판단 기준

대상 목록과 최신 관측은 [공식 기준표](sources/CURRENT_SHOP_COVERAGE.md)와 [구조화 원문 기준](../data/research/probability-scope-baseline.json)을 따른다. 2026-10-25 13:45 UTC 관측은 7명단이며, 개수를 상수로 고정하지 않는다. 일본어 표·캠페인·특별판·전체 웹상점으로 모수를 넓히지 않는다. 지역·기기 추가 선택을 대상 확정의 선행 질문으로 되돌리지 않는다.

- 해당 공식 회차의 **모든 특수 카드**에 출시 카드 ID·수량·타입·상품 연결·이름·이미지·표시 OVR이 필요하다.
- **Standard 실명·실제 ID 목록은 불필요하다. 익명 Standard 모델 방향은 승인됐고 실제 구현은 후속 작업이다.** 같은 회차의 공식 초기 수 `N`과 완전한 특수 수량 `S`로 `A=N−S`를 검증한다.
- 특수 종류 누락·unknown 타입·중복·다른 회차 혼합을 Standard 수량으로 숨기지 않는다. 전역/역사 카드 전수를 다시 선행 게이트로 두지 않는다.
- 공식 표가 제공하지 않는 시작·가격/재화·옵션·리셋·계정 자격을 추정하지 않는다. 출처 표시 OVR은 조건 미확인을 함께 표시할 수 있지만 공식 최대 능력이라고 주장하지 않는다.
- 기존 9상품·83카드·관측은 보존할 이전 표본이며 새 대상의 완료 수가 아니다. 수명주기는 [데이터 보존 계획](DATA_LIFECYCLE.md)을 따른다.

근거 표기는 **검증**(실제 응답/코드/행 검사), **선언**(공급자 설명/메타), **미확인**(근거 미확보), **제외**(현재 조건상 자동 공급 불가)로 구분한다. 공개 200은 이용·저장·재배포 허가가 아니다.

## 필수 선정 게이트

모든 게이트가 통과하기 전 **최종 선정**으로 기록하지 않는다. 통과는 공급자 전체가 아니라 검증한 대상/필드/권리 범위에 한정한다. 조합을 쓰면 각 공급자의 권리와 교차 회차/카드 매핑을 검증한다.

| 게이트 | 필수 근거·통과 산출물 |
| --- | --- |
| G0 대상 | 최신 KR 원문·URL/시각/해시·실제 항목 수·초기 N·종료·미확인 필드. 숫자 7을 고정하거나 빈/손상 응답을 전부 종료로 처리하지 않음 |
| G1 권리·비용 | 자동 접근 경로/빈도·원문 보관·정규화 저장·파생 공개·이미지 **로드/저장/재배포**·출처표기·철회/삭제 조건·상업 여부·쿼터·가격. 연락 페이지/공개 200으로 대체 불가 |
| G2 특수 전체·회차 | 각 공식 회차에 대응한 **모든 특수 종류의 출시 카드 ID·수량**과 전체성 근거. 여러 소개 그룹·페이지 경계·중복/누락·unknown을 검사. 팀 스쿼드/전역 variant/추천 목록을 대입하지 않음 |
| G3 필드·전수 이미지 | 모든 대상 특수 카드의 이름·표시 OVR·타입 원문·상품 연결·provenance. **각 이미지의 실제 로드→형식/디코딩→허용 저장→다시 읽기→해시/카드 연결** 검사. URL·표본 PNG·hotlink만으로 통과 금지 |
| G4 익명 Standard | 동일 회차 공식 N·완전 특수 수량 S·`A=N−S≥0`, unknown/누락 특수 0건. 초기/계정 잔여·실제/합성 수량 분리. Standard 실명·실제 카드 ID 목록은 불필요 |
| G5 공급자 갱신·가용성 | 허용 최신 발견 방식·schema/버전/생성/관측시각·해시. 공급자의 실제 변경 전후 자료와 신규/수정/종료 반영 증거, 오류/축소·요청량/비용·이전 버전 취급. 단발 200/주간 문구로 통과 금지 |
| G6 대체 계약 | 공급자 중립 ID·원본 매핑·필드/조건 provenance·공통 오류 상태·멱등성/실패 보존 fixture. 실제 B 공급자 동시 확보를 최초 채택 조건으로 추가하지 않되 실제 대체 가능성은 별도 검증 표시 |

현재 미통과를 제거하기 위해 기준을 낮추지 않는다. **T009에서 선정 검증용 비활성 자료 수집/실험을 수행한다.** 모든 대상의 특수 manifest·필수 필드와 실제 이미지의 허용 저장/디코딩/재읽기 전수 probe까지 확인해 G0~G6 통과 후에만 최종 선정한다. 이 검증에는 DB 스키마 구축·정규화 DB·활성 import가 없다. T010의 선정 후 정식 수집 파이프라인/staging 편입과 구분한다.

G5의 공급자 변경 증거와 새 R5/T015~T016의 자체 자동 갱신·API 운영 검증은 별개다. 공급자 선정만으로 우리 스케줄/복구가 가동 중이라고 기록하지 않는다.

## T009에서 바로 수행할 순서

1. **근거 고정:** 공식 기준 JSON·기존 응답/해시·현재 후보표를 읽는다. 상품 대응·특수 집합·필수 필드·이미지·권리·갱신 공백을 상품별로 기록한다. 이미 성공한 raw부터 재사용한다.
2. **권리/정상 경로:** EFHub·PesLig의 이용조건을 먼저 확인한다. 부족하면 PESDATABASE.com/TheWinningXI 등의 명시 허용 feed·샘플·조건을 협의 검토 후보로 남긴다. 이번 계획에서 연락·가입·계약이 실행됐다고 쓰지 않는다.
3. **검증 계약:** 정확히 공개/제공된 경로·쿼리·범위·예산·중단 조건·응답 계약·이미지 저장권한·예상 비용을 정한다. 기존 거부 재시도, endpoint/버전 추측, 키/토큰 취득을 일정에 넣지 않는다.
4. **회차·특수 전체:** 가장 작은 대상 1개부터 공식 회차와 연결하고 모든 특수 종류·카드 ID·수량을 대조한다. 다음에는 당시 KR 대상 각각에 같은 기준을 적용한다. 소개 그룹을 근거 없이 합치지 않는다.
5. **비활성 전수 probe:** 모든 대상 특수 manifest의 이름·타입·OVR 원문/조건을 확인한다. 허용된 이미지 전체를 실제 로드·형식/디코딩·저장·재읽기·해시/카드 연결까지 검사하고 비활성 검증 보고서를 남긴다. URL/표본 성공은 대체 근거가 아니며 이미지 실패를 Standard로 채우지 않는다. DB 스키마·활성 import는 하지 않는다.
6. **실제 갱신/오류:** 허용된 전후 관측과 공급자 버전/변경 자료를 비교한다. 실제 변화가 없으면 ‘변화 미관측’으로 남긴다. 단발 성공을 안정성으로 올리지 않는다.
7. **검증 보고서:** G0~G6별 증거·성공/선언/미확인·범위·실패 이유·권리/비용을 기록한다. 하나라도 필수 미통과이면 최종 선정을 보류하고 다음에 필요한 정확한 증거를 남긴다.
8. **최종 선정·인계:** 모든 게이트가 통과한 대상/역할별 공급자만 최종 선정한다. T010에는 통과 snapshot·이미지 probe·권리/경로·raw/provenance 계약을 넘긴다. T011에는 정규화/DB 후 개별 카드·수량·모든 이미지 연결을 다시 검증할 기준과 보고서를 넘긴다. 미통과면 T009를 완료하지 않는다.

## T010 수집 → T011 개별 검증·DB 표본

- **T010/R2:** T009 최종 선정 후 정식 수집 파이프라인을 만들고 통과한 snapshot/probe를 staging에 편입한다. 원문·이미지·권리·버전이 여전히 유효하면 다시 다운로드하지 않는다. 새로운 허용 delta/개정본만 수집하고 raw/해시·문자열 ID·시각/schema·권리·요청 결과를 보존한다. 전역/역사 수집은 추가하지 않는다.
- **T011/R2:** 정규화·DB 표본 저장 후 특수 누락/중복/타입·판본·수량·상품 연결과 모든 이미지의 디코딩·저장 후 재읽기·해시/내부 카드 연결을 다시 검증한다. T009의 probe만으로 정규화 후 연결 검사를 생략하지 않는다. 실패·손상·조건 충돌은 이전 정상 데이터에 영향을 주지 않는다.
- T009에서 당시 모든 대상의 특수 manifest/이미지는 이미 전수 검증한다. T011은 그중 상품 1개의 정규화 DB 표본·N/S/A·내부 연결을 재검증한다. 이후 T014 전체 대상 DB 편입 때 모든 연결의 재검증을 확장하며, T009의 전수 검증을 미루는 뜻이 아니다. 합성 Standard는 실제 확보 카드 수와 분리한다.
- T009의 선정용 probe, T010 정식 수집, T011 정규화/DB 검증, 공개·스케줄 운영을 별도로 기록한다. 새로운 revision의 전수 이미지 검증이 실패하면 그 revision을 발행하지 않고 마지막 정상 자료를 보존한다. 원문 보유만으로 권리가 충족된 것으로 처리하지 않는다.

## 중립 ID·OVR·공급자 대체 계약

- 상품 회차·출시 카드·관측의 내부 ID는 공급자와 독립시킨다. 외부 ID는 `(provider, id_type, original_string)`으로 매핑한다. 기존 ID/URL을 일괄 재발급하지 않고 alias/매핑으로 보존한다.
- 공식 응답 순번은 영구 상품 ID가 아니다. 명시 교차 ID가 없으면 공식 명단/종료·공지/배너와 공급자의 회차·특수 카드 근거로 검증한 관계를 `round_verified`로 기록한다. 이름 유사 `candidate`와 구분한다.
- 이름·같은 숫자 ID·비트마스크만으로 실인물·출시 카드·판본을 합치지 않는다. 같은 사람의 다른 카드가 같은 풀에 있으면 서로 다른 구성일 수 있다.
- OVR은 **값+조건/판본+출처 관측**으로 다룬다. 새 값에 이전 훈련/부스터 조건을 붙이지 않는다. 조건 미확인은 표시하되 공식 최대값·동일 조건 정확성을 주장하지 않는다.
- PesLig/EFHub 83 ID가 겹치지만 OVR 14건과 타입 차이가 있다. `Other Special`·`is_variant`·non-Standard를 공식 특수 분류로 자동 치환하지 않는다.
- 어댑터는 raw 메타/권리 참조, 외부/내부 ID·연결 근거, 필드 provenance·조건, 상품별 범위/특수 완전성, 이미지 저장/검증 결과를 공통 계약으로 반환한다.
- `success`/`partial`/`blocked`/`schema_changed`/`identity_conflict`/`conditions_conflict`/`coverage_shrink`를 구분한다. 빈 응답·403·축소·오래된 관측·충돌이 정상 데이터를 지우거나 되돌리지 못하게 한다.
- 공급자 교체 fixture는 같은 회차 A/B 계약·긴 ID·중복·수량2·이미지 손상·권리 만료·중단/재실행·멱등성을 포함한다. B는 mock으로 계약을 검사할 수 있으며 실제 B 공급자의 권리/자료/대체 검증은 별도로 표시한다. EFHub CDN을 공유하는 사이트는 독립 이미지 장애 대안으로 세지 않는다.

## 익명 Standard 수량 검증

1. 초기 N과 같은 회차의 **완전한** 특수 수량 S를 확인한 뒤 A를 계산한다. unknown 타입·누락·중복·음수·분수·초기/잔여 혼동은 실패다.
2. S는 검증된 출시 카드별 수량의 합이다. 소개 그룹 중복 노출은 중복 수집인지 확인하고, 실제 관계 수량2는 보존한다. 이름으로 중복 제거하지 않는다.
3. European Midfielders의 공식 Epic3+Highlight8에서 소개8명만 확보했다고 `150−8=142`를 Standard로 만들지 않는다. 누락 Epic3를 먼저 검증한다. Magical 소개11도 회차/특수 전체 검증 전에는 S=11로 확정하지 않는다.
4. N=11 명단에서 같은 회차의 특수11개가 모두 검증되면 A=0일 수 있다. 숫자11 일치만으로 완료시키지 않는다.
5. 합성 그룹은 실제 선수/카드·외부 ID·실측 이미지/OVR·‘확보한 실제 카드 수’와 분리한다. 가상 수량·근거·검증 시각을 저장하며 가짜 원본 ID를 만들지 않는다. 연출은 [후속 시뮬레이터 계획](SIMULATOR_PLAN.md)을 따른다.

## 권리·비용·갱신 완료 기록

권리는 데이터와 이미지에 각각 적용한다. 수집/원문 저장·정규화 DB·공개 API/사이트·캐시/재배포·출처표기·만료/철회 범위를 분리하고 제한을 어댑터 계약에 연결한다. 다른 공급자로 조합해도 빠진 권리를 대신 충족하지 못한다.

비용은 요청량·snapshot/이미지 바이트·변경 빈도·보관/백업·재검증·feed 이용료를 측정한다. 무료 공개 페이지의 무제한 이용을 가정하지 않는다. Pages 우선 배치와 한도·자산 저장소/OCI 비교는 [배포 계획](DEPLOYMENT.md)을 따르며 지금 유료 서비스·인프라 변경을 실행하지 않는다.

최종 선정 기록에는 대상 시점/범위, 역할별 provider, G0~G6 보고서, 미기재 게임 규칙, 허용 요청량·비용, 실제 갱신 근거, 이미지 전수 저장 결과, 장애/교체 한계를 포함한다. 작업마다 [WORKPLAN](WORKPLAN.md)의 이전/현재/다음·추가 조건과 [FILE_SYNC](FILE_SYNC.json)의 관련 파일/우선순위를 갱신한다.
