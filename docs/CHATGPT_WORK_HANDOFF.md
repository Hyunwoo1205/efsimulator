## 2. 최신 목표: 전체 누적층과 사이트층 분리

### A. 전체 누적 DB/API

EFHub에서 정상적으로 확보 가능한 **모든 선수 카드와 선수팩**을 가공한다. 새 원본 ID를 추가하고 기존 엔티티는 삭제하지 않는다. 동일 ID의 정보가 바뀌면 새 개정과 관측을 저장해 이전 값과 근거를 보존한다. 사용자의 ‘추가, 삭제하지 않음’은 잘못된 값을 영원히 고정한다는 뜻이 아니다. 검증된 최신 참조와 과거 개정을 함께 관리한다.

원문에 있는 Standard 실명 카드, 과거 카드, 다른 출시 버전도 보존한다. 이름이 같아도 다른 카드 ID를 합치지 않는다. 빈 응답, 오류, 출처 목록에서의 일시적인 누락을 삭제로 해석하지 않는다. 원문·정규화·원본 문자열 ID 매핑·개정·팩과 카드의 관계 이력·검증 manifest를 분리한다. 전체 DB/API용 폴더와 서버는 실제 자료 크기, 조회 요구, 권한, 비용을 검토한 뒤 선택한다. 아직 새 DB/API는 구축하지 않았다.

### B. 사이트용 현재 판매 DB와 배포 스냅샷

유일한 대상 기준은 **https://efootball-web.konami.net/probability_kr.php** 이다. 최신 정상 전체 목록, 정확한 회차, 종료 UTC, 관측 신선도를 검증한 현재 유효 팩과 해당 카드만 전체 누적층의 특정 버전에서 추출한다.

판매 변동에 따라 사이트의 활성 목록은 추가·수정·제외할 수 있다. 전체 누적층의 엔티티와 과거 발행본은 보존한다. 전체 누적 범위와 사이트 대상 범위를 서로의 완료 수로 사용하지 않는다.

공식 페이지에 없는 시작일, 가격·재화, 무료 횟수, 다회 할인·제한, 복원·리셋 규칙은 추측하지 않는다. 과거에 표에 있었다는 사실만으로 현재 판매 중이라고 표시하지 않는다. 빈 응답이나 파서 실패로 모든 상품을 종료시키지 않는다. 마지막 정상본을 유지하더라도 이미 지난 종료 시각을 무시하고 현재 판매·시뮬레이션 가능으로 표시하지 않는다.

### 유지하는 상세 요구

- 감독은 상품 구성, 활성 검색·상세, 시뮬레이션에서 일괄 제외한다. 일부만 수동 연결하는 혼합 정책은 금지한다. 원본 항목 내부의 중첩 필드는 손실 없이 보존하되 별도 감독 수집은 하지 않는다. 실제 상품에 감독이 없다는 뜻은 아니다.
- 구매 즉시 일괄 획득하는 고정 팩은 누적 목록에 보존할 수 있지만 개봉 시뮬레이터에서 제외한다. 코인 결제 여부와는 별개다.
- 같은 회차의 모든 특수 카드가 완전함을 검증했을 때만 공식 초기 총원 `N`에서 특수 슬롯 수 `S`를 뺀 `A = N − S`를 익명 Standard 그룹으로 만든다. 미확인 타입, 특수 카드 누락, 다른 회차 혼합, 중복, 음수 차이가 있으면 준비 완료로 표시하지 않는다. 실제 카드·선수 ID를 위조하지 않는다. 누적층의 실제 Standard도 해당 팩의 포함 근거 없이 넣지 않는다.
- 데이터·자동 갱신·자체 API 운영을 검증한 뒤 시뮬레이터와 3D를 구현한다. 가상 Standard에도 모션을 제공할 계획이다. 추첨·잔여 풀·다회·리셋은 검증된 규칙만 구현한다. 연출 건너뛰기, 동작 줄이기, 키보드·스크린리더, 로드 실패 fallback, 모바일 성능, 3D 자산 권리 검증을 포함한다. 현재는 구현하지 않았다.

이전 50,840개와 최종 47,397개의 차이인 **3,443개는 사용자 설명상 중복 제거 결과**다. 현재 파일의 고유 ID 47,397개와 중복 0개는 별도 오프라인 검증으로 확인했다. 원본 페이지·중복 제거 로그는 이 환경에서 재검증하지 않았다는 한계만 유지한다. 누락 의심을 주요 차단 요인으로 삼거나 전체를 재수집하지 않는다. 배열에 페이지·total 메타가 없으므로 원래 2,119페이지를 완주했음을 이 파일만으로 증명한 것은 아니다.

**두 raw만으로 팩과 카드를 조인할 수 없다.** 팩 원문에 카드 ID와 선수 명단이 없으므로 이름 추측으로 연결하지 않는다. 기존 Work에 상세·관계 자료가 이미 있는지 먼저 확인하고, 검증된 팩 회차와 카드 ID 명단·출처 근거를 확보한 뒤 정규화 설계로 넘어간다. playerCount 합계나 slug 유일성만으로 관계·공식 전체 구성의 완전성을 주장하지 않는다.

원래 페이지 완전성은 로그와 별도 확인 상태다. 이를 불필요한 전수 재수집이나 전체 진행 차단으로 연결하지 않는다. 양쪽 원본은 변경하지 않았고 EFHub·이미지 요청은 0회다. 팩 검사와 함께 선수 raw의 SHA도 기존 값과 같음을 재확인했다.

`scripts/merge-api-pages.mjs`는 **페이지 래퍼·메타가 있는 파일**을 입력받는 오프라인 병합 도구다. 이미 합쳐진 배열에 가짜 페이지 메타를 넣어 입력하지 않는다. 실제 raw와 합성 테스트 fixture를 섞지 않는다. 도구 테스트 68개 통과는 실제 자료의 전수 확보 성공을 뜻하지 않는다.

## 4. 기존 구현과 미구현 범위

기존 구현에는 이전 범위의 상품 9개와 카드 83개가 있다. 상품 연결 카드는 79개, 독립적인 다른 버전 카드는 4개이며 감독은 0명이다. 단일 seed → SQLite → 정적 JSON, 한국어 검색·상세·양방향 탐색, 관측·개정·실패 보존, seed 누적 보존, 오프라인 페이지 병합 도구, 관리 검사와 Node 테스트 224개가 있다.

아직 없는 것은 새 전체 누적 DB/API, 두 계층 저장·발행, 현재 판매 필터, 공식 회차 매핑, `N/S/A` 모델, 모든 팩의 상세 관계, 이미지 전수 저장·권리 검증, 실제 자동 갱신·백업 운영, 시뮬레이터·3D다. 원래 raw 페이지의 완전성과 현재성도 미검증이다. 기존 상품 9개는 판매 상태가 `unknown`, 기간이 `null`, 구성이 `partial`이므로 현재 판매 DB나 새 완성본으로 사용하지 않는다.

## 6. EFHub 경로와 과거 차단 기록

확인된 GET 경로는 다음과 같다. 모두 과거 관측이며 이번에 요청하지 않았다.

1010은 Cloudflare 보안 차단 유형의 근거다. 구체적인 규칙, 모든 API에 대한 차단, 과거 본문 없는 403의 동일 원인을 증명하지는 않는다. 사이트 선방문, 쿠키·토큰·UA·프록시 변경으로 접근 제한을 우회하거나 거부 요청을 반복하지 않는다. 정상 지원 API·export·운영자 허용 경로가 필요하면 구체적인 조건을 정리한다. 외부 연락, 계정, 새 권한·비용은 이번에 추가하지 않았다.

EFHub는 사용자가 우선 지정한 공급원이다. 보유 raw의 오프라인 검증과 지속 접근, 갱신 주기·비용, 저장·재배포 권한, 정확한 팩 특수 집합, 이미지 검증은 별개다. PesLig 비교는 보존 기록이다. 사이트 자체 API를 KONAMI 원본 API라고 부르지 않는다. `dt870_console_win.cpk`는 파일 컨테이너명이며 API 주소가 아니다.

## 9. 배포와 의도적 이관 제외

기존 Cloudflare Pages와 별도 Sites는 다르다. Pages의 실제 대시보드 빌드 명령, 출력 폴더, 운영 브랜치, 환경 변수는 아직 확인하지 않았다. 코드상 `npm run build` → `dist`, Node.js 24.19.0은 확인됐지만 과거의 `exit 0`·루트 안내를 현재 설정이라고 단정하지 않는다. main이 초기 커밋이므로 전역 설정을 먼저 `dist`로 바꾸지 않는다. 검토용 배포 → 사용자 검토 → 명시적 운영 반영 승인을 구분한다.

**별도로 만든 Sites 초기 페이지, 해당 Site 소스·index.html·번들은 사용자의 결정으로 이관에서 제외한다.** Sites 복원·재사용·재생성·수정·삭제 작업을 요구하지 않는다. 본 저장소의 실제 앱 `web/index.html`과 루트 호환 `index.html`은 보존하며 별도 Sites 초기 페이지와 혼동해 삭제하지 않는다.

정적 Pages의 초기 읽기 JSON과 전체 누적 동적 API를 분리한다. 방문자 GET에서 외부 출처를 수집하지 않는다. Workers·D1·무료 서버·OCI A1 2 OCPU/12GB ARM64는 실제 요구, 접근 권한, 한도, 비용, 백업을 검토해 선택한다. OCI 사양은 사용자 승인 계획에 기재된 것이며 실제 접속·가용성은 검증하지 않았다. 3D 때문에 즉시 이전하지 말고 파일 수, 단일 파일 25MiB 제한, 전송량, 모바일 GPU 성능, 압축·LOD·지연 로딩·자산 분리를 실측한다. R2 등은 초과 요금이 발생할 수 있으므로 활성화 전에 비용을 제시한다.

## 10. GitHub work로 이어가기와 선택 백업

기존 대상 Work에서 **GitHub work를 우선 읽는다.** 현재 수집 출력과 사용자 변경을 보존한 상태로 원격을 fetch해 HEAD와 비교한다. main만 읽으면 앱과 최신 계획이 없다. 새 채팅, 대체 저장소, 중복 수집을 만들지 않는다.

```bash
cd /actual/path/to/existing/efsimulator
git status --short
git branch --show-current
git rev-parse HEAD
git ls-remote origin refs/heads/main refs/heads/work
git fetch origin work
git log --oneline --left-right HEAD...FETCH_HEAD
git diff --stat HEAD FETCH_HEAD
```

현재 변경과 선조 관계를 확인한 뒤 누락된 work 커밋을 반영한다. reset·clean·강제 checkout·강제 push로 현재 작업을 덮어쓰지 않는다. 이번 푸시 승인은 해당 work 반영과 기존 CI·preview 실행 범위이며 새 기능, main 병합, 서비스 설정, 자동화 활성화에 대한 포괄 승인이 아니다.

선택 백업은 현재 실행 환경의 다음 경로에 있다. 다른 Work로 자동 전달된다고 가정하지 않으며 필요할 때만 별도 파일로 받는다.

- `artifacts/migration/efsimulator-work.bundle`: work Git 이력·참조의 선택 백업. 필요하면 `git bundle verify`, `git bundle list-heads`로 receipt와 대조한다.
- `artifacts/migration/MIGRATION_RECEIPT.json`: 최종 로컬·원격 SHA, 검사·CI, bundle 해시·크기.
- `artifacts/migration/IGNORED_ARTIFACTS.json`: Git 비추적 산출물의 경로·크기·해시 목록. 실제 원문 백업이 아니므로 필요한 고유 자료는 별도로 전달한다.

선수 raw v1은 필요한 환경에서 Library 지원 흐름으로 읽고 위 SHA와 대조한다. 같은 파일을 다시 수집하지 않는다. credential·env·쿠키와 별도 Sites 초기 소스는 이관에 포함하지 않는다. 이 문서 작업 환경에는 Library 업로드 도구가 없으며 상위 채팅에서 별도 지원 환경으로 MD 저장을 진행한다. 이 작업이 새 `library_file_id`를 발급했다고 주장하지 않는다.

## 11. 다음 작업 순서와 대상 Work에 넣을 지시

1. 기존 대상 Work에서 GitHub work의 최신 SHA와 현재 HEAD·사용자 변경을 비교하고 누락 커밋을 반영한다. bundle은 필수가 아니다. 파일 목록과 현재 작업 상태를 읽는다.
