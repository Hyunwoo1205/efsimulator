# 공식 대상 수집·검증 계획

새 범위는 [공식 KR 확률표](sources/CURRENT_SHOP_COVERAGE.md)의 당시 게재 목록과 그 안의 **모든 특수 카드**다. 실명 Standard·전체 전역/과거·감독·별도 상점·다른 버전 수집은 하지 않는다. 기존 EFHub CLI·감사 도구/표본은 보존하지만 새 대상 자동 수집기로 확정하지 않았다. 기존 명령과 실패 보존 계약은 [이전 구현 기록](reference/COLLECTION_BEFORE_PROBABILITY_SCOPE.md)에 둔다.

공식 페이지에는 ID·가격·재화·시작·리셋·다회 규칙이 없다. 미기재값을 이름/타입/게시일로 보완하지 않는다. 최초 영입의 N/확률과 계정 잔여 명단은 구분한다. 공식 게재 여부와 카드 manifest 완전성·기능 준비도를 각각 저장한다.

## 수집 제약과 실패 처리

- 허용된 정상 공개 경로/공급자 문서만 사용한다. 새 feed가 없으면 추측 endpoint·헤더 위장·쿠키/토큰 취득·프록시 변경·접근 거부 우회로 대체하지 않는다. 이미 거부된 요청을 반복하지 않는다.
- 원본과 정규화를 분리하고 요청 예산·단일 동시성·공급자가 허용한 속도·checkpoint/재개를 정의한다. timeout/5xx는 제한된 다음 정규 실행 정책,403은 자동 접근 중단/검토로 처리한다. 구체 주기는 공급자 조건과 운영 예산을 통과한 후 확정한다.
- 200이라도 HTML오류/빈자료/스키마변경/미완료페이지/급감이면 정상으로 게시하지 않는다. HTTP·MIME·원문크기/해시·비밀을 제외한 헤더·파서버전·검증오류를 기록한다. 향후 허용된 진단은 cf-error-type/cf-error-origin/cf-ray도 allowlist에 포함하며 기존 미보존 값을 새 요청으로 보충하지 않는다.
- 이미지URL이 있다는 것만으로 성공하지 않는다. 모든 대상 특수 카드의 실제응답·형식/디코딩·허용 저장·저장후재읽기·해시·카드연결을 검증한다. cache/hotlink/재배포 권리를 따로 남기며 저장 권한 미확인은 선정/공개 전 해결한다.
- 유형이 다르거나 미확인인 비Standard를 익명 Standard에 포함하지 않는다. 가상 그룹은 실제 수집 수/선수ID와 분리한다. 세부 조건은 [ARCHITECTURE](ARCHITECTURE.md)를 따른다.
- 수집실패·누락·일시소멸은 원본/공개 정상 데이터 삭제 요청이 아니다. 얇은 아카이브·상태전이·single-writer·last-good·원자적manifest·백업 복구는 [DATA_LIFECYCLE](DATA_LIFECYCLE.md)에 정의한다.

## 기존 검증과 이번 작업 경계

기존 EFHub 소개79카드와 별도Yaya4카드는 저장 표본이다. 공식7대상 중 이름/시기 후보5·충분한 후보 미확인2, 공식 명시ID 연결/전체 특수 검증0이라는 이전 결과를 선정 근거로 보존한다. 이전 players의limit100 403은 본문/헤더 미보존으로 원인 미확정이다. 새 상품 검색/상세403을 그 원인으로 전용하지 않는다. 과거 전역 감사는 재실행 선행 조건이 아니다.

이전 T008에서는 공식 원문1회 재관측과 계획 문서만 변경했다. 현재 T009의 실제 선정 검증은 [실행 결과](sources/API_SELECTION_VALIDATION.md)에 기록한다. 선정 조건 미통과로 정식 수집/활성 편입은 시작하지 않았다. CLI/스키마/DB/활성seed·공개JSON·배포·스케줄을 바꾸지 않는다. `data:prepare`는 저장 표본 재현이며 인터넷 수집/새 범위 편입 명령이 아니다.

## 별도 중간 작업: 전체 원본 페이지의 오프라인 병합

18:09 UTC 추가 요청은 실제 DB를 만들기 전 players/packs 전체 원문 항목을 각각 배열로 합치는 것이다. 현재 허용된 구현은 [오프라인 병합 도구](RAW_PAGE_MERGE.md)와 합성 테스트뿐이다. 공식7팩의 최종 DB 범위와 구분하며, 네트워크/브라우저 선방문·쿠키/토큰·상세/관계/이미지·배포는 실행하지 않는다.

기존 players 관측에는 일부 표본만 있고 전체 raw page 파일이 없다. packs는 연구 JSON 안에2쪽60행의 파싱 응답이 있으나 전체1698개 원본이 아니다. 연구 래퍼를 실제 원문 페이지로 가장하거나 재직렬화한 해시를 원래 HTTP 본문 해시로 주장하지 않는다. 이번에는 이 부분 자료를 요청된 전체 산출물로 내보내지 않는다.
