# 원본 API 페이지의 오프라인 중간 병합

> T021 최신 입력 검증: 부모 환경이 Library v1을 오프라인 검증: 유효 배열47,397객체/고유 문자열ID47,397, 중복ID·충돌·중복키0. SHA256 16b5ac4919480bbbf8e5158946322fac1f406f0d66701c4d52c9274107dc94c4. 페이지/출처/수집시각/total 메타가 없어 전수·현재성은 미검증이며, 사용자가3,443차이는중복제거결과라고설명했다. 원본페이지/중복제거로그는재검증하지않았다는한계만유지하고packs준비를이어받는다. 원본 변경·EFHub/이미지 요청은 없었고 packs 수집 준비/상세 매핑·이미지 실로드는 별도다.

> 최신 진행 상태: 대상 Work 채팅에서 players raw는 제작 완료 보고, packs 수집은 **준비 중**이다. 그 채팅의 기존 출력/체크포인트/계획을 먼저 확인해 이어받으며 새 채팅·중복 수집을 만들지 않는다. 준비 상태를 수집 완료로 표시하지 않고 팩 상세/카드 매핑도 별도 검증한다.

T019는 네트워크 접근 없이 **원본 페이지 JSON 파일을 입력받아 players 배열과 packs 배열을 각각 하나의 JSON 배열로 합칠 도구**를 준비한 작업이다. T019 당시 전체 원본이 없어 이 도구로 실제 전체 선수/팩 산출물을 생성하지 않았다. 실제 DB 가공 도구는 아니다. T020의 최신 계획에서는 검증된 raw를 전체 누적 DB/API의 입력으로 보존하고, 사이트용 현행 DB는 그와 별도로 추출한다.

## 다른 Work에서 제공한 배열 원본과의 구분

다른 Work의 `players_raw.json` v1은 부모 환경에서 실제 오프라인 검증했다. 최상위 배열47,397개 객체/고유 문자열ID, 중복0이며 SHA/필수필드 존재를 확인했다. 원본 페이지/커서/출처/수집시각/total 메타는 없어 페이지 완전성·현재성은 미검증이다. 이전50,840과의3,443차이는사용자설명상중복제거결과다. 원본중복제거로그는재검증하지않았지만누락의심을차단요인으로삼지않고전체재수집/가짜페이지메타생성을지시하지않는다. 실제 이미지/팩 관계는 별도다. 상세 결과는 [인수인계](CHATGPT_WORK_HANDOFF.md)를 따른다.

이미 합쳐진 JSON 배열에는 원본 페이지의 `page`/`limit`/`total` 등이 없을 수 있다. 이런 파일은 **이 페이지 병합 도구의 직접 입력이 아니다.** 원본을 수정하거나 페이지 메타를 지어내지 않고 별도의 오프라인 배열 감사를 수행한다. 실제 행 수/고유 ID/필드 검사와 페이지 전수 완전성 증명을 분리한다. 사용자 관측 50,840과 2,119는 출처·시점·전체 페이지 근거가 연결되기 전까지 대조 기대값일 뿐이다.

이미지 URL의 존재/형식 검사는 실제 다운로드·디코딩·허용 저장/재읽기 성공과 다르다. 이번 문서 점검과 원본 오프라인 검증에서는 이미지 네트워크 다운로드나 EFHub 재수집을 하지 않는다.

## 필요한 입력

정상 허용 API/export 또는 사용자가 제공한 **각 페이지의 원본 응답 JSON**을 종류별 디렉터리에 둔다. 연구 보고서·메타 발췌·카드 표본·HTML은 원본 페이지 입력이 아니다. 이 도구에는 사이트 선방문·인증 활성화·쿠키/토큰·다운로드 기능이 없다.

한 페이지는 다음 정보를 직접 포함해야 한다.

- `players` 또는 `packs`: 해당 페이지 항목 배열. 두 종류는 따로 처리한다.
- `page`, `limit`, `total`: 페이지 번호·페이지 크기·출처가 보고한 전체 수. 기대값 인자로 대신하지 않는다. 계수 메타(`totalPages` 포함)는 소수/지수 없이0또는양의10진 정수 토큰으로 받아 부동소수 반올림을 차단하고 안전한 정수 범위를 검증한다. 항목 내부 숫자의 보존과는 별개다.
- `totalPages`, `hasMore`: 제공된 경우 전체 수/마지막 페이지와 일치해야 한다. `totalPages`가 없어도 실제 `total`/`limit`에서 계산한 전체 범위와 모든 페이지·행 수를 검증한다.
- 항목 식별 필드: 기본값은 선수의 `id`, 팩의 `slug`. 다른 계약은 `--id-field`로 명시한다. 팩에 별도 `id`가 있으면 그 중복도 검사한다.

기존 체크아웃에 보존된 players의 두 성공 관측은 일부 표본만 남았고 전체24명 응답 파일은 없다. packs는 연구 JSON 안에1·2쪽 각30행이 있으나 독립 원문 바이트/전체 페이지가 없다. 새 Library 배열과 이 과거 표본/페이지 발췌의 출처를 혼합하지 않는다. 기존60행을 전체 선수팩 파일로 내보내지 않는다.

## 원본 페이지 입력이 따로 제공된 경우의 실행 예시

Node.js24.19.0·npm11.9.0, 추가 의존성 없이 실행한다. 입력 폴더의 JSON 파일은 모두 같은 종류의 원본 페이지여야 한다. 출력·보고서는 입력 폴더 밖의 별도 경로를 사용한다.

출력/보고서의 부모 디렉터리는 먼저 준비한다. 아래 예시는 원본이 준비된 후 실행하는 명령이다.

```bash
mkdir -p artifacts/intermediate
npm run data:merge-pages -- --kind players \
  --input-dir artifacts/raw/players \
  --output artifacts/intermediate/players.all.json \
  --report artifacts/intermediate/players.validation.json \
  --expected-total 50840 --expected-pages 2119

npm run data:merge-pages -- --kind packs \
  --input-dir artifacts/raw/packs \
  --output artifacts/intermediate/packs.all.json \
  --report artifacts/intermediate/packs.validation.json
```

위의 `50840`과 `2119`는 사용자 관측값을 **선택적 기대값**으로 전달한 예시다. 현재 전수 확보 수나 서버의 최신 값이 아니다. 실제 메타와 다르면 실패 보고서에 기록하며 부족한 페이지나 항목을 생성하지 않는다. 메타가 없는2119파일만으로 완료 처리하지 않는다.

`node scripts/merge-api-pages.mjs --help`에서도 인자를 확인할 수 있다. 이 명령은 오프라인 로컬 파일만 읽는다. 실제 원본과 합성 fixture는 별도이며 테스트 fixture를 `artifacts/raw`나 실제 산출물에 넣지 않는다.

## 보존과 검증

파일명이나 파일 정렬을 페이지 순서로 믿지 않고 입력의 `page`로 순서를 결정한다. 각 페이지의 원래 항목 순서는 유지한다. 바깥 players/packs 래퍼와 페이지 메타는 배열 출력에서 분리하고 검증 보고서에 남긴다. 항목 내부에 있는 `total`/`page` 같은 이름의 필드도 삭제하지 않는다.

출력 항목은 원본 JSON 조각을 보존한다. 알려지지 않은 필드·긴/선행0 문자열ID·중첩 객체/배열·null·숫자 리터럴을 임의 변환하지 않는다. 이름/타입/OVR 계산·키 이름 변경·ID 재발급·중복 제거는 하지 않는다.

검증 보고서는 입력 파일과 페이지 순서/해시, 항목 수, 메타/기대값, 중복 페이지/ID와 충돌, 누락 페이지 범위, 합계/마지막 페이지 불일치 등을 기록한다. 중복 항목을 조용히 제거해 숫자를 맞추지 않는다. 잘못된 JSON·메타 부재·빈 자료·다른 종류/알 수 없는 바깥 필드는 실패로 취급한다.

완전성은 **제공된 입력 메타와 항목에 대한 내부 검증 결과**다. 실제 원출처·최신성·이용권한·현재 팩의 모든 특수 카드 포함·이미지/DB 검증까지 증명하는 것은 아니다. 일부 자료의 오류를 고쳐 보이게 하거나 partial을 complete로 표시하지 않는다.

모든 필수 검증을 통과해야 최종 배열을 쓴다. 불완전/오류 입력에서는 보고서만 기록하고 기존 배열 출력과 원본 파일을 보존한다. 출력/보고서/입력의 같은 경로·별칭 충돌은 거부한다. 종료 코드는0(입력 기준 완전·배열 생성),1(불완전/잘못된 원본·보고서만 생성),2(인자/경로/쓰기 실패)다. `complete`, `summary`, `pages`, `errors`, `warnings`와 `scope`가 보고서의 주요 항목이다. 중복의 `same_payload`는 원문 문자열 일치이고 형식 차이까지 의미적 값 충돌이라고 확정하지 않는다. 출력/보고서는 각각 rename으로 발행하고 최종 보고서 발행 실패 시 기존 배열을 복구한다. 두 파일의 시스템 중단까지 포함한 단일 트랜잭션은 아니다.

## 현재 위치와 다음 작업

도구의 합성 테스트 통과와 실제 전수 원본 확보/병합 성공은 구분한다. T021에서는 부모가 검증한 `players_raw.json` v1을 기준으로 기존Work의 수집 로그/페이지 체크포인트·원본 메타/manifest를 대조하고, 준비 중인 팩 raw 상태를 이어받는다. 정상적으로 제공된 전체 raw **페이지**가 별도로 확보된 경우에만 이 도구로 각각 `players.all.json`, `packs.all.json`을 만들고 실제 행 수/페이지/해시/누락을 보고한다. 다른 Work의 배열을 T019의 생성 산출물로 주장하지 않는다.

이번 T020은 문서 점검·인수인계와 제공 원본의 오프라인 확인이며 EFHub 네트워크 요청·브라우저 선방문·403/1010 반복·인증/우회는 하지 않는다. 실제 새 DB 제작·팩 상세 HTML/API 조사·선수↔팩 관계 연결·이미지·자동 갱신·배포는 후속 구현 단계다. 전체 누적 엔티티/개정을 무삭제로 보존하는 정책과, 공식 확률표·종료시각·신선도에 맞춰 사이트 활성 대상을 추가/수정/제외하는 정책을 분리한다. 최신 상태는 [WORKPLAN](WORKPLAN.md)을 따른다.
