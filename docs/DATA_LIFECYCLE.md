# 전체 누적 자료와 사이트용 현행 자료의 수명주기 계획

> T021 최신 입력 검증: 부모 환경이 Library v1을 오프라인 검증: 유효 배열47,397객체/고유 문자열ID47,397, 중복ID·충돌·중복키0. SHA256 16b5ac4919480bbbf8e5158946322fac1f406f0d66701c4d52c9274107dc94c4. 페이지/출처/수집시각/total 메타가 없어 전수·현재성은 미검증이며, 사용자가3,443차이는중복제거결과라고설명했다. 원본페이지/중복제거로그는재검증하지않았다는한계만유지하고packs준비를이어받는다. 원본 변경·EFHub/이미지 요청은 없었고 packs 수집 준비/상세 매핑·이미지 실로드는 별도다.

> 최신 진행 상태: 대상 Work 채팅에서 players raw는 제작 완료 보고, packs 수집은 **준비 중**이다. 그 채팅의 기존 출력/체크포인트/계획을 먼저 확인해 이어받으며 새 채팅·중복 수집을 만들지 않는다. 준비 상태를 수집 완료로 표시하지 않고 팩 상세/카드 매핑도 별도 검증한다.

T020 최신 사용자 결정에 따라 **EFHub 전체 누적 DB/API**와 **공식 KR 현행 대상의 사이트용 DB/배포 스냅샷**을 분리한다. 이번 작업은 문서 점검·계획·인수인계뿐이며 실제 수집·DB/API·발행·스케줄을 새로 구현하거나 활성화하지 않는다. 현재 단계·작업은 [ROADMAP](ROADMAP.md)과 [WORKPLAN](WORKPLAN.md), 논리 스키마는 [ARCHITECTURE](ARCHITECTURE.md)를 따른다.

전체 누적 계층은 정상적으로 확보 가능한 모든 EFHub players/packs를 가공·보존한다. 기존 엔티티는 삭제하지 않고 신규ID를 추가하며 기존 값 변경은 개정본과 근거를 보존한다. 원본에 포함된 Standard 카드와 종료/일괄 지급 팩도 이 계층에서 보존할 수 있다. 감독 지원과 상품↔감독 관계는 일괄 제외하고 raw 내부 필드는 손실 없이 보존한다.

사이트용 계층은 [공식 한국어 확률표](https://efootball-web.konami.net/probability_kr.php)의 현재 유효 회차와 연결 카드만 추출한다. 관측된7개를 고정하지 않는다. 현재 게재·종료시각·원문 신선도를 함께 검증하며 전체 누적 레지스트리와 다른 속도로 추가/수정/활성 제외될 수 있다. 일괄 구매·지급 팩은 개봉 시뮬레이터에서 제외한다. 사이트의 익명 Standard는 검증된 특수 수와 공식 초기 총원의 차이만 표현하고 전체 카드 카탈로그의 실제 Standard 목록을 임의로 팩에 넣지 않는다.

선수 raw v1의 행/ID/필드/SHA는 부모 환경의 실제 오프라인 검증으로 확인됐다. 원본 페이지·수집시각/출처 메타는 없어 전수/현재성은 미검증이며 기존 Work 체크포인트/완료 로그와 대조한다. 전체 재수집을 지시하지 않는다. 팩 raw는 대상 Work에서 수집 준비 중이고 상세 관계는 별도다.

현재 저장 기록의 공식 필드는 이름, 최초 선수 수, 최초 확률과 조건, UTC 종료시각이다. 안정 게임 상품ID·판매 시작·결제 재화/옵션/제한·전체 개별 카드·계정 잔여 수는 미확인이다. 자체 API의 공개 범위는 확보 범위와 별개로 이용·보관·재배포 권한을 검증한다.

## 1. 전체 누적 계층의 추가·개정·무삭제

전체 누적 수집 결과는 불변 raw와 검증 보고로 등록한 뒤 원본ID 단위로 비교한다. 새 ID는 엔티티를 추가하고, 기존 ID의 의미 있는 변경은 새 개정본과 필드·관계 근거를 추가한다. 기존 레지스트리 행과 이전 개정본은 삭제하거나 덮어쓰지 않는다. 동일 입력 재실행은 새 엔티티/동일 개정본을 중복 생성하지 않고 재관측만 기록한다.

원본에서 누락되거나 최신 수집 창 밖으로 이동한 항목은 ‘이번 실행에서 미관측’으로 기록한다. 원본 삭제·판매 종료·게임 내 존재 여부의 근거로 바꾸지 않는다. 최신 응답만으로 seed를 다시 만들어 과거 누적 항목을 축소하는 경로를 금지한다. 기존 카드는 정보 정정을 받아들일 수 있지만 확인값을 미확인/null로 자동 덮지 않고 값과 조건의 변경 이력을 남긴다. 관계 변경도 버전과 유효 범위를 보존하며 수집 일부 누락만으로 이전 연결을 지우지 않는다.

누적 계층의 불변 버전·manifest·원문 저장소와 사이트용 불변 버전·manifest·캐시는 각각 관리한다. 사이트 후보는 특정 누적 버전과 공식 관측을 참조한다. 누적 갱신이 성공해도 사이트 회차/완전성·신선도가 미확인이라면 사이트 버전을 바꾸지 않을 수 있다. 사이트 목록에서 팩을 제외해도 누적 원본/팩/카드/관계 이력은 남는다.

원본·누적 정규화 자료는 기본 비공개 보존하고 자체 전체 API의 외부 공개는 별도 권한 검증을 거친다. 보관 용량이 커지면 압축·해시 중복 제거·분할·저렴한 저장 계층을 검토하며 일반 엔티티 삭제를 기본 비용 절감 수단으로 삼지 않는다. 법적 삭제 의무·잘못 저장한 비밀 정보 등은 기록된 별도 예외이며 원본 미관측과 구분한다.

## 2. 사이트용 계층의 갱신과 상태 전이

공식 원문 관측과 서비스에 공개한 마지막 정상 자료를 분리한다. 매 실행은 원문 수집, 구조·필드 검증, 변경 후보 작성, 후보 전체 검증, 공개 버전 작성, 마지막 정상 버전 교체 순서로 진행한다. 검증 전 후보가 현재 자료를 덮어쓰지 않게 한다. 현재 저장된 자료를 삭제하고 다시 채우는 방식은 사용하지 않는다.

사이트의 각 상품은 아래 상태와 별도로 공식 게재 여부, 검증 상태, 마지막 정상 상태, 종료 근거, 최근 관측 시각을 갖는다. 따라서 통신 장애와 상품의 실제 변화를 구분할 수 있다.

- 공식 게재: 정상 문서에서 새 행을 관측한 상태다. 공식 페이지 안에 있다는 뜻이며 수집 카드·가격·시뮬레이터 준비까지 완료됐다는 뜻이 아니다.
- 검증 대기: 신규 행이나 필드 변경을 원본과 대조하는 상태다. 새 값은 후보에 보존하고 공개된 정상 개정본은 유지한다.
- 활성: 대상 공식 표에 현재 게재되고 확인한 종료 시각 전이며, 해당 공개 필드의 검증을 통과한 상태다. 표가 제공하지 않는 재화·가격·카드 전체성은 계속 미확인이다.
- 종료 확인: 검증된 명시 종료 시각이 지났고 종료 시각 이후의 정상 공식 관측에서 연장·정정이 없음을 확인한 상태다. 종료 시각과 확인 시각을 따로 보존한다.
- 아카이브: 현행 뷰에서 제외하고 얇은 기록을 보존한 상태다. 명시 종료와 지속 미게재의 보관 사유를 구분한다.
- 불확실: 공식 행 소멸의 재확인 중이거나 동일 상품·회차 구별, 종료 연장, 필드 충돌을 해결하지 못한 상태다. 마지막 확인값과 불확실 사유를 보여 주고 판매 중·종료를 단정하지 않는다.

신규는 공식 게재→검증 대기→활성으로 진행한다. 변경은 검증 대기인 새 개정본을 만들고 검증 후 공개 버전을 바꾼다. 검증 실패 시 이전 공개 개정본을 유지한다. 같은 원문·동일 정규화 내용의 반복 관측은 관측 이력만 추가하고 상품 개정본을 중복 생성하지 않는다.

변경 판정은 공식 필드·검증된 카드·공개 상태의 의미 있는 값으로 계산한다. 요청 시각·최근 확인 시각·관측 로그·health만 달라진 실행을 카탈로그 변경으로 취급하지 않는다. 이 정보는 운영 기록과 health에 따로 저장해 변경 없음 실행에서 공개 버전 이동·Pages 빌드를 생략할 수 있게 한다.

상품의 이름·최초 수·종료 시각은 수정될 수 있으므로 이 셋의 결합을 영구 상품 ID로 쓰지 않는다. 공식 상품 ID를 확보하지 못한 행은 내부 회차 ID와 관측 원문의 행 위치를 분리한다. 같은 표의 같은 이름에 대응하는 살아 있는 회차가 하나라는 근거가 있을 때만 기존 회차의 수정 후보로 연결한다. 동명 재출시·이름 변경·동시 중복 행이 모호하면 병합하지 않고 불확실로 보류한다. 내부 ID를 게임 원본 ID라고 표시하지 않는다.

### 소멸과 명시 종료의 재확인 정책

정상적인 단일 미게재만으로 종료나 삭제를 결정하지 않는다. 첫 미게재는 불확실로 두고 마지막 정상 기록을 보존한다. 재확인 제안 기본값은 서로 다른 정규 실행의 정상 전체 문서 3회, 관측 간격 최소 30분, 최초·최종 관측 간격 최소 2시간이며 실측 검토 후 확정한다. 24시간보다 긴 공백이 있으면 연속 재확인 계수를 다시 시작한다. 실패·빈 문서·파서 실패·거부 응답은 계수에 포함하지 않는다.

3회 확인 후에도 미게재이면 공식 목록에서 제외됐다는 사실만 확정한다. 원래 명시 종료 시각이 없거나 아직 미래라면 실제 판매 종료로 바꾸지 않는다. 현행 뷰에서 제외하고 아카이브 사유를 ‘공식 목록의 지속 미게재’로 보존하며 실제 종료 시각은 미확인으로 남긴다. 이 경로는 명시 종료 확인을 거친 아카이브와 다르다.

명시 종료가 지난 경우에도 마지막으로 알던 종료 시각만으로 수정 가능성을 지우지 않는다. 종료 이후 정상 관측에서 같은 종료가 유지되거나 목록에서 제외된 것을 확인하면 종료 확인으로 전환한다. 그 시점에 출처를 읽지 못하면 ‘마지막 확인 종료 시각 경과·재확인 미완료’로 표시한다. 확인된 종료 자료는 현행 목록에서 즉시 분리하고 기본 24시간의 정정 대기 후 얇은 아카이브로 옮긴다.

불확실·아카이브 자료가 다시 나타나면 신규 또는 정정 후보로 검증한다. 기존 종료 기록을 소급 삭제하지 않는다. 같은 회차의 기간 정정인지 새 회차인지 입증할 수 없으면 자동 재사용하지 않는다.

## 3. 실패 보호와 두 계층의 공개 정합성

일반 수집의 제안 기본값은 시간당 1회·UTC 매시 10분이다. 출처 동작과 실행 예산을 실측 검토한 뒤 확정하고, 출처를 조회하는 스케줄은 이 문서 작성에서 활성화하지 않는다. 명시 종료와 가장 가까운 다음 정규 실행에서 종료를 재확인하므로 날짜 경계마다 별도 요청을 무제한 추가하지 않는다.

HTTP 403은 해당 실행과 자동 수집을 중지하는 회로 차단 상태로 기록한다. 운영자가 정상 경로·정책을 검토해 재개하기 전 다른 URL·헤더·인증으로 우회하거나 정규 실행마다 같은 거부 요청을 반복하지 않는다. 시간 초과·5xx는 같은 실행에서 연속 재시도하지 않고 다음 정규 실행을 기다린다. 파서 실패는 원문을 보존하고 저장한 원문으로 파서를 검증한 뒤 재개한다.

HTTP 200도 비어 있거나 예상 문서·행 구조·필수 값이 부족하면 정상 자료로 승격하지 않는다. 정상 자료가 있던 상태에서 빈 결과를 받아도 활성 목록을 비우지 않는다. 공식적으로 대상이 없음을 나타내는 문서 구조를 별도로 검증하기 전까지 전체 빈 목록은 검토 대기다. 미만료 행이 한 번에 3개 이상 또는 기존 목록의 절반을 넘게 사라지는 후보도 자동 승인하지 않는다. 이미 명시 종료된 행의 정상 정리와 파싱 누락을 구분해 검토한다.

단일 쓰기 실행만 허용한다. 예약 실행과 수동 실행은 같은 작업·동시 실행 잠금 경로를 사용하며, 잠금을 얻지 못한 실행은 쓰지 않고 종료한다. 후보가 시작할 때 읽은 공개 버전과 현재 공개 버전이 달라졌으면 게시를 중단하고 다시 비교한다. 로컬 명령이 운영 저장소에 직접 쓰는 우회 경로는 만들지 않는다.

새 버전에는 원문 해시, 관측과 검증 결과, 정규화 자료, 현행·불확실·아카이브 인덱스와 파일 해시를 먼저 기록한다. 모든 참조와 체크섬을 검사한 뒤 현재 버전을 가리키는 작은 manifest만 마지막에 원자적으로 교체한다. 로컬 파일시스템은 같은 파일시스템의 rename, 객체 저장소는 단일 객체 교체와 이전 버전 일치 조건을 사용한다. 선택한 저장소가 이 조건을 지원하는지는 운영 전 시험한다.

API 소비자는 manifest를 한 번 읽고 그 버전에 속한 자료만 읽는다. 서로 다른 최신 경로를 각각 읽어 새 상품과 옛 카드가 섞이지 않게 한다. 실패·일시 빈 값·검증 대기 동안 마지막 정상 공개 버전은 유지한다. 장애 경고와 마지막 확인 시각은 별도 health 자료로 갱신할 수 있지만, 장애를 빈 상품 카탈로그로 게시하지 않는다.

사이트 대상 자격은 `정상 전체 공식 관측 + 같은 회차 매핑 + 종료 전 + 검증된 신선도`를 함께 요구한다. 마지막 정상 버전 보존이 오래된 상품을 계속 판매 중으로 표시하라는 뜻은 아니다. 마지막 확인 종료시각이 지났거나 신선도를 통과하지 못하면 읽기 시점의 현행/시뮬레이션 자격을 해제하고 ‘종료시각 경과·재확인 미완료’ 또는 ‘오래된 자료’로 표시한다. 출처 실패는 누적 엔티티 삭제나 전체 목록의 종료 확정으로 바꾸지 않는다.

출처의 최근 정상 확인이 제안 기본값 3시간을 넘으면 API와 화면에 오래된 자료라는 표시를 붙인다. 이 경고가 모든 상품의 실제 종료를 뜻하지는 않는다. 출처 실패 2회 연속은 운영 경고, 마지막 정상 확인 후 24시간 경과·복구 불가·게시 무결성 실패는 긴급 점검으로 분류한다. 알림은 상태 변경이나 필요한 조치가 생겼을 때만 보내며 매 실행의 동일 경고를 반복하지 않는다.

## 4. 사이트의 얇은 아카이브와 공용 이미지 수명

종료 상품의 모든 화면·대용량 이미지를 현행 API에 계속 싣지 않는다. 아카이브 기본 보존물은 내부 회차 ID와 제목·최초 수·확률 조건·원문 기간, 확인한 카드 명단과 그 완전성 범위, 출처 URL·시각·해시, 변경·종료·소멸 사유, 검증 결과다. 종료됐다는 이유로 새로운 과거 자료를 추가 수집하지 않는다.

공식 원문은 해시별로 중복 제거해 압축 보관한다. 정상 문서가 같으면 같은 원문을 재사용하고 관측 기록만 추가한다. 작은 메타·명단·근거·검증 아카이브와 공식 원문은 기본 영구 삭제 대상이 아니다. 오래된 공개 인덱스는 분할하거나 저렴한 보관 계층으로 옮길 수 있지만 원본 기록을 삭제해 비용을 줄이는 것을 기본 전략으로 삼지 않는다. 보관량·요청량·복구 가치가 측정된 뒤 별도 변경 계획으로 보존 정책을 조정한다.

사이트 아카이브는 전체 누적 계층을 대체하거나 그 엔티티를 축약 삭제하는 작업이 아니다. 사이트에 필요한 얇은 뷰와 누적 원문/개정본은 별도 보존한다.

아카이브 API와 현행 API의 인덱스·캐시를 분리한다. 현행 검색이 과거 전체 기록을 다운로드하지 않게 하고, 개별 아카이브 조회는 별도 경로에서 필요한 회차만 읽는다. 작은 메타·명단·근거·검증 요약은 장기 보존하되, 공개 범위는 이용 권한이 확인된 필드로 제한한다.

원문 raw는 기본 비공개 영구 아카이브에 두고 공개 API의 저장소·권한과 분리한다. 수집자는 필요한 원문 쓰기, 읽기 API는 공개 정규화 버전 읽기, 운영자와 백업 작업은 승인한 원문·복구 범위만 접근한다. 공개 URL에서 저장소 경로를 추측해 raw를 읽을 수 없게 검증한다. 비공개 보존 권한도 확인하지 못했거나 삭제 의무가 있는 경우에는 예외와 보존 가능한 최소 근거를 별도 검토한다.

이미지는 기본적으로 확인한 원본 URL·해시·출처·권리 상태를 보존한다. 로컬·객체 저장소에 캐시할 권한과 비용이 검증된 경우에만 파일을 저장한다. 이미지 정리는 실제 원본 상품 데이터 삭제와 별개다.

캐시 파일의 삭제 후보는 현재 공개 자료, 정정 대기 자료, 복구 가능한 최근 버전과 백업에서 참조되지 않고, 마지막 참조가 끝난 뒤 제안 기본값 90일이 지난 파일이다. 이 기간은 실제 이미지 용량·재사용·권리 조건을 검토해 확정한다. 참조 수는 실제 manifest·아카이브 보존 정책·복구 보존 기간을 기준으로 계산한다. 단순히 활성 상품 참조가 0이라는 이유로 즉시 지우지 않는다. 얇은 아카이브는 이미지 원본 URL과 해시만 유지할 수 있으므로 그 메타 참조가 캐시 파일의 영구 보관 의무와 같은 뜻은 아니다.

권리·보존 필요·정리 목록을 검토한 뒤 캐시 파일만 제거하고 실행 결과를 기록한다. 원본 URL·해시·출처·대상 관계는 남긴다. 잘못 보관한 파일이나 명시적 삭제 의무는 별도 예외로 처리한다. 외부 이미지가 없어지면 자체 API는 이미지 미확인·접근 실패를 표시하며 임의 대체 카드나 유사 이미지를 실제 이미지로 채우지 않는다.

## 5. 전체 누적 API와 사이트용 읽기 API의 저비용 운영

자체 API는 공식 자료를 대신 주장하는 새 원출처가 아니라 검증한 자료의 읽기 인터페이스다. 전체 누적 API는 확보한 카드/팩·매핑·개정본/변경 커서·검증/확보 범위와 누적 버전을 제공하는 계층이다. 사이트는 여기서 필요한 현재 회차의 자료를 내려받아 사이트용 DB/스냅샷을 만든다. 전체 raw·이미지의 외부 공개는 포함된 것으로 간주하지 않고 권한을 따로 확인한다.

사이트용 읽기 API의 첫 계약은 버전 manifest, 현행 목록, 불확실 목록, 상품 상세, 사이트 아카이브 인덱스·회차 상세, health 자료다. 전체 누적 API와 사이트 API의 경로·접근권한·페이지네이션·캐시·배포 주기는 분리한다. 같은 서버/폴더에 둘지 별도 서버로 둘지는 검증할 운영 선택이며 지금 새 서버를 생성하지 않는다. 각 응답은 범위, 공개 버전, 원본 관측 시각과 검증 수준을 포함한다. 존재하지 않는 ID는 404, 자료가 오래됐지만 정상 버전이 있는 경우에는 기존 자료와 오래됨 표시를 제공한다. 장애 때 빈 배열 200으로 바꾸지 않는다.

예를 들어 서로 분리된 논리 네임스페이스 `/catalog-api/v1/`와 `/site-api/v1/` 아래 manifest·불변 버전·health를 둘 수 있다. 누적 API에는 페이지/변경 커서가, 사이트 API에는 당시 대상/상품/아카이브 인덱스가 필요하다. 이는 **미구현 인터페이스 제안**이며 현재 저장소에 이 API가 존재하거나 배포됐다는 뜻이 아니다. T016에서 서비스 범위·버전 계약·파라미터/오류·캐시 검증과 함께 최종 경로를 고정한다.

manifest와 health의 캐시 기본값은 60초이며 ETag를 사용한다. 버전 경로의 불변 자료는 긴 캐시를 적용한다. 현행 인덱스와 아카이브 인덱스는 별도로 저장해 종료 처리 때문에 과거 전체 자료를 무효화하지 않는다. 새 게시 전후의 버전 일관성과 만료·새로고침 동작을 실제 CDN에서 검증한다.

정적 Pages JSON도 자체 읽기 API로 제공할 수 있다. R2/R3의 제한된 표본과 공개 검색·조회만 필요하면 버전별 JSON과 manifest로 시작하고, 클라이언트에서 검색·필터를 처리한다. 이 경우 스케줄러는 원본 수집과 검증을 담당하고, 변경이 있을 때만 검토된 데이터 버전을 게시한다. 정적 배포에 성공했다는 사실을 수집 스케줄 가동으로 기록하지 않는다.

무료 Pages 빌드 예산은 월 500회를 계획 상한으로 두고 실제 계정 조건을 운영 전에 확인한다. 시간당 상시 빌드는 한 달 약 720회 이상이므로 이 구성의 기본 운영 방식이 될 수 없다. **변경 없음이면 빌드·게시를 건너뛰는 처리가 필수**이며, 원문 관측·health 갱신을 사이트 전체 빌드와 분리한다. 변경이 많아 실제 빌드 예산을 넘는 경우에도 모두 건너뛰어 최신성을 숨기지 말고 데이터 게시를 앱 배포와 분리하거나 갱신 주기·호스팅 계획을 재검토한다.

앱 전체 재배포 없이 자료·health를 갱신해야 하거나, archive의 서버 페이지 조회·조회 제한·권한·서버 검색이 필요해지면 얇은 동적 읽기 API를 추가한다. 추천 후보는 무료 범위의 Cloudflare Worker와 객체 저장소이며, 저장한 불변 버전을 읽어 응답하는 기능부터 시작한다. 실시간 원출처 수집을 사용자 GET 요청에 연결하지 않는다. 운영 DB의 SQL 검색이 필요하다는 측정 근거가 생기기 전까지 별도 상시 DB 서버를 필수로 두지 않는다.

기본 스케줄러 후보는 기존 저장소의 GitHub Actions 예약 실행과 같은 작업의 수동 dispatch다. 예약·수동의 single-writer 잠금, 실제 실행 지연, 인증 범위, 게시 동작과 무료 한도를 먼저 확인한다. 수집 상태·관측 원문·불변 공개 버전은 runner 임시 디스크가 아닌 영속 저장소에 둔다. Git에는 관리 가능한 얇은 자료·스키마·설정만 두고 큰 이미지·반복 원문·비밀값을 넣지 않는다. 정확한 스토리지 공급자와 게시 인증은 아래 운영 진입 조건을 충족한 뒤 확정한다.

무료 운영 진입 조건은 예상 시간당 요청·실행 시간·보관 용량·API 호출과 응답 트래픽이 확인된 무료 할당량 안에 들어오는지, 기존 Pages와 새 읽기 경로가 함께 동작하는지, 자동 유료 전환이나 초과 비용의 통제 수단이 있는지, 필요한 인증이 준비됐는지다. 이 문서 작성에서는 계정 한도·인증·연결 가능 상태를 새로 확인하지 않았다. 비용·접근 권한·영속 저장·백업 중 하나라도 준비되지 않으면 운영 미완료로 기록하고 API와 스케줄이 가동 중이라고 표시하지 않는다.

무료 서버리스 구성이 기능·한도·실제 접근 요건을 만족하지 못할 때 차선으로 보유 OCI A1 Flex 2 OCPU·12GB ARM64를 검토한다. OCI에서는 Node.js 24.19.0·npm 11.9.0, 단일 쓰기 프로세스·타이머·SQLite와 읽기 API를 구성할 수 있다. ARM64 의존성, TLS·방화벽·외부 접근, 프로세스 재시작, 영속 볼륨·독립 백업·복구·실제 비용을 확인하기 전 사용 가능하다고 판정하지 않는다. 보유 인스턴스라는 사실을 접속 준비·무료 운영 보장으로 바꾸지 않는다.

## 6. 백업·검증·운영 시작 조건

게시마다 직전 manifest와 불변 공개 버전을 보존해 포인터 복구가 가능하게 한다. rollback 보존의 제안 기본값은 최근 정상 버전 최소 7일이며 작은 원문·메타 아카이브는 별도로 계속 보존한다. 매일 한 번 변경 기록·회차 레지스트리·원문 참조·현재 manifest를 묶어 독립 저장 위치에 백업하고, 백업 보존의 제안 기본값은 최근 30일이다. 두 기간은 복구 시험·저장량·비용을 실측 검토해 확정한다. 독립 위치와 비용이 준비되지 않았으면 운영 진입 미충족으로 표시한다. 공개 쓰기 인증 하나의 손실로 원본과 백업이 함께 삭제되지 않게 권한을 분리한다.

복구 목표의 제안 기본값은 RTO 30분, RPO 24시간이다. 잘못 게시한 자료를 이전 정상 버전으로 30분 이내 되돌리고, 독립 백업만 남은 장애에서 최대 24시간의 메타 변경 손실 안으로 복구한다는 목표이며 달성 결과는 아니다. 실제 복구 연습으로 시간·손실 범위·비용을 측정해 확정한다. 원본 공급자의 자료를 다시 받을 수 있다는 가정으로 백업을 생략하지 않는다. 운영 전 복구 연습을 하고 이후 월 1회 저장 백업을 실제로 읽어 무결성과 포인터 복구를 확인한다.

health에는 최근 시도·정상 확인·성공 게시 시각, 현재 공개 버전, 수집 차단 여부, 검증 대기 수, 오래된 자료 여부와 백업 최신성을 표시한다. 비밀값·인증 헤더·내부 접근 경로는 공개 health에 넣지 않는다. 원문 응답 상태와 파서/게시 오류를 구분해 어떤 단계가 실패했는지 운영 기록으로 추적한다.

운영 전 검증에는 누적 엔티티 수의 무단 감소 방지, 최신 수집 창에서 이전 항목이 사라진 뒤에도 fresh 환경에서 누적 이력 재현, 기존ID 정정의 이전 개정본 보존, 누적/사이트 버전 혼합 방지를 포함한다. 사이트 상태 검증은 다음 사례를 포함한다. 신규 한 행, 종료 연장·초기 수 변경, 같은 원문의 재실행, 한 번만 사라진 행의 복귀, 3회 지속 미게재, 명시 종료 뒤 정상 확인, 출처 장애 중 종료 시각 경과, 동명 재출시와 모호한 이름 변경, HTTP 403·5xx·일시 빈 문서·파서 실패·대량 누락, 두 실행의 동시 쓰기, 후보 파일 누락·잘못된 체크섬·manifest 교체 실패, 이전 정상 버전 복구, 참조 중 이미지의 정리 차단을 저장 fixture와 실제 운영 전 시험으로 확인한다.

## 가상 Standard의 G 게이트

가상 Standard 모델 방향은 이미 사용자 승인됐고 실제 구현은 후속 단계에서 수행한다. 모델 승인과 상품별 데이터 검증은 별개이며, 실제 생성·자체 API 제공 전에 다음 G 게이트를 모두 통과해야 한다.

- 같은 공식 상품·회차에서 최초 수 N과 그 관측 시각·조건을 확인한다. 계정별 현재 남은 수를 최초 수로 대체하지 않는다.
- 모든 비Standard 특수 카드의 출시 카드 식별·구성·수량 S가 정확하고 완전함을 검증한다. 대표 카드만 확보한 목록, 빠진 Highlight, 중복·복수 분류를 합산한 수량은 완전한 S가 아니다.
- 남은 N-S가 Standard라는 근거와 분류의 전체성을 확인하고 N-S가 음수가 아닌 정수인지 검증한다. 차이가 남는다는 사실만으로 Standard라고 판정하지 않는다.
- 가상 풀은 별도 종류와 개수로만 표현한다. 선수 실명·카드·원본 게임 ID를 생성하지 않고 실제 확보 카드·실존 선수 수·출처 ID와 분리한다. 상품 회차·N·S·근거가 변경되면 G를 다시 검증한다.

하나라도 미충족이면 가상 Standard 수를 확정하지 않고 미확인으로 남긴다. 이 문서는 슬롯 생성·추첨·모션·3D를 구현하거나 활성화하지 않는다.

## T015·T016의 운영 완료 조건

R3의 사용자 운영 승인과 R4의 전체 공식 대상 DB가 선행 조건이다. T015는 신규·수정·명시 종료·소멸 재확인의 전후 관측, 검증·게시 결과, 실패 때 마지막 정상 버전 유지와 복구 결과를 남긴다. 단순 fixture 성공이나 반복 HTTP 200만으로 실제 변경 반영을 검증했다고 판정하지 않는다. 검증 기간에 실제 변화가 없으면 그 항목은 운영 관찰 대기로 남긴다.

T016은 제안 API의 실제 구현·공개 응답·버전 정합성·캐시·health, 스케줄러·영속 저장·백업 복구, 권한과 무료 예산·비용 통제를 확인한다. 누적의 신규/개정·무삭제, 사이트의 추가/수정/활성 제외, 각 계층 변경 없음 실행의 빌드/게시 생략과 유효 변경의 실제 반영을 각각 검증한다. 대상 범위·상품 회차 대응·미확인 필드와 G 통과 여부를 화면과 API가 일관되게 표시해야 한다.

권한·비용·저장소·백업·가용성이 준비되지 않았거나 실제 신규/수정/종료 반영의 운영 증거가 없으면 해당 운영 항목은 미완료다. 최초 정상 실행을 계획서 작성, 정적 배포 성공, 스케줄 구성 저장으로 대신하지 않는다. 완료한 코드와 준비된 운영, 실제 가동·검증 결과를 WORKPLAN에 구분해 기록한 뒤 R6의 시뮬레이터·3D 단계로 연결한다.
