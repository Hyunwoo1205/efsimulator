# 데이터 갱신·전체 아카이브·자체 API

T024(2026-10-27)의 사용자 지시가 최신 기준이다. [전체 파일/필드 계약](CATALOG_DATA_CONTRACT.md), [현재 작업](WORKPLAN.md), [배포 경계](DEPLOYMENT.md)를 함께 따른다. 이전의 전체 raw 공개 API, 얇은 아카이브, 종료 후 24시간 대기 제안은 대체되었다.

## 범위와 순서

원본은 기존 JSON 형식으로 누적한다. 신규 상품이 공식 KR 확률표와 EFHub 양쪽에서 같은 회차로 확인되어야 HTML 수집을 시작한다. new-players와 필요한 상세 HTML만 읽으며 원본 API를 조회하지 않는다. 기존 raw ID와 순서를 보존하고 신규 ID/slug만 추가하며 선수·팩 raw 로그를 각각 쓴다.

가공 DB는 이 중 공식 게재 상품으로 확정한 팩과 그 선수만 누적한다. 선수는 정확히 지정 8개 필드만 포함한다. 관계는 가공 팩의 members에 저장한다. 팩의 특수 인원과 공식 전체 인원·UTC 종료를 구분하고, 원본 오류는 근거 있는 보정값과 원본값을 함께 둔다.

그 다음 종료된 live 항목을 선수 상세 전체와 함께 archive에 옮기고, 새로 확정한 현재 유효 상품을 가공 DB에서 중첩하여 live에 추가한다. 가공 선수/팩·live·archive가 바뀔 때마다 대상 파일과 ID·전후 수·전이·근거를 API 로그에 남긴다. live와 archive는 가공 팩의 완전한 분할이며, 선수의 중복 제거 합집합이 가공 선수 전체와 같다.

## 실패와 시간

403/429/challenge는 해당 EFHub 수집 실행을 중단한다. 거부 요청을 즉시 반복하거나 헤더·쿠키·프록시·토큰을 바꾸어 우회하지 않는다. 다음 예약 실행에서는 정상 HTML 요청만 확인할 수 있다. 빈 문서·부분 HTML·파서 오류·시간 초과·2시간보다 오래된 공식 관측은 신규 발행이나 상품 삭제 근거가 아니다.

이미 검증한 UTC 종료 시각은 출처 장애 중에도 적용한다. 종료와 공식 정상 전체 목록의 미게재는 각각 ended와 official_removed로 보존한다. 같은 제목의 종료/인원 변경은 새 검증 후보가 필요하며 이전 회차의 현재성을 추정하지 않는다. 재판매와 같은 회차의 정정을 입증할 수 없으면 자동 합치지 않는다.

예약 실행 사이에 종료가 도래하면 HTTP live 조회는 서버 UTC로 제외하고 archive 조회는 그 전체 자료를 포함한다. GET에서 파일·DB를 수정하지 않는다. 영속 파일 이동과 로그는 다음 갱신에서 확정한다. API ready를 전체 공식 범위 완성으로 표현하지 않는다.

## 원자적 파일과 DB 발행

scripts/lifecycle/workspace.mjs는 raw/processed/live/archive/logs를 불변 versions/<hash>/에 기록한다. 모든 참조·분할·수·파일 해시를 확인한 뒤 CURRENT.json을 원자적으로 바꾼다. 이전 세대와 원본 바이트는 보존한다. 쓰기 잠금과 expectedVersion으로 동시 수정 손실을 방지한다. 변화 없는 점검은 checks.jsonl만 갱신한다.

scripts/lifecycle/publication.mjs는 가공 자료만 담은 불변 D1 버전을 만든다. 모든 chunk를 적재하고 실제 DB 레코드와 내용 해시를 비교한 뒤, 이전 활성 버전 조건을 건 단일 포인터 전환을 실행한다. 부분 업로드·내용 충돌·잘못된 참조·오래된 쓰기는 활성화하지 않는다. API는 요청마다 포인터를 한 번 읽고 같은 버전으로만 조회한다. 기존 staging 테이블로 대체 조회하지 않는다.

run-cycle.mjs의 --db는 로컬 SQLite 검증 대상이다. 원격 D1은 Sites에 등록/배포한 뒤 원격 수입 경로로 적재하고 읽어 검증해야 한다. 로컬 성공을 원격 API 운영 성공으로 바꾸지 않는다.

## 현재 상태

raw 47,408선수/1,699팩을 보존했다. 공식 HTML7상품 중 기존 정확한 카드 ID 관계로 확정한 4팩44선수를 가공했고 live4/archive0이다. 실제 로컬 API7경로의 200과 중첩 자료를 확인했다. 미확정3상품은 대기한다. EFHub 수집기 HTML403으로 이번 신규 원본 수집은0건이다. 수집 파서는 합성 HTML 및 저장한 공식 HTML로 검증했으며 실제 EFHub 원문 파싱 성공은 아직 아니다.

매시간 점검 예약은 Asia/Seoul 기준으로 활성화했다. 아직 첫 예약 실행 성공·실제 Site 등록/배포·원격 D1 수입·서비스 인증·비용/백업 복구 검증을 완료하지 않았다. 후속 T025에서 남은 관계와 정상 공급·검토 배포를 확인한다. 시뮬레이터와 3D는 이 데이터/운영 검증 뒤의 작업이다.
