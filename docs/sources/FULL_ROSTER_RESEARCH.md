# 상품별 전체 선수 명단과 Standard 확보 조사

현재 핵심 범위는 [현재 상점과 그 구성 카드](CURRENT_SHOP_COVERAGE.md)다. 아래 당시 전역/과거/다른 버전 확장 계획은 최신 범위의 필수 완료 조건에서 보류하며 조사 이력으로 보존한다. 상품별 소개/전체 초기 풀·미확인과 익명Standard 보류는 계속 구분한다.

기존 R1/T002·R4/T005·R5/T006 범위에서 C023/C024를 보강한 조사다. 관측일은 2026-10-25이며, 구조화한 근거는 [조사 기록](../../data/research/roster-source-observations.json)에 둔다. **Standard를 포함한 상품별 초기 전체 추첨풀을 반환하는 공개 API는 이번 조사에서 확보하지 못했다.** 그런 API가 존재하지 않는다는 증명은 아니다. 활성 데이터·상품 관계·배포 설정은 변경하지 않았다.

## 403 원인과 확인 가능한 한계

목록 감사의 `GET /api/public/players?page=1&limit=100`은 05:02:17 UTC에 403을 반환했다. 당시 코드는 비200에서 본문·응답 헤더를 읽기 전에 중단했다. 남은 자료는 URL·시각·상태와 로컬 오류 메시지뿐이므로 **출처 서버, CDN, 환경 프록시 중 어느 계층이 반환했는지와 직접 원인은 미확정**이다.

별도 선수 상세 API에 저장된 JSON 오류 본문은 다른 URL·다른 시각의 응답이다. 목록 실패의 본문으로 사용할 수 없다. 이전 기본 목록과 2쪽의 200도 시간·요청 조건이 다른 관측이므로 파라미터 하나만 바꾼 통제 비교가 아니다.

공개 JS의 보존 발췌는 초기 무쿼리 목록·이후 `?page=n`과 로컬 `limit:24`를 보여준다. `limit=100`을 만드는 기본 UI 옵션이나 이를 지원한다는 공식 API 계약은 확인하지 못했다. 서버가 지원하지 않는다는 결론도 이 403만으로 낼 수 없다. 요청 보호 초기화 코드, 출처/CDN 정책, 중간 네트워크 정책은 각각 가설이며, 현재 unrestricted 환경 설정은 과거 거부의 원인을 소급 증명하지 않는다. [상세 진단](CARD_API_AUDIT.md)을 따른다.

동일 실패 요청·다른 쿼리로 재감사하거나 쿠키/토큰·UA·프록시·TLS를 바꾸지 않았다. 원인 확인에 필요한 최소 자료는 공급자의 허용 API 경로·파라미터·쿼터/자동 접근 조건 및 해당 시각의 거부 사유다. 현재 기록에는 공급자에게 전달할 응답 request ID도 없다. 새 계정이나 자격 증명이 필요하다고 단정하지 않는다. 이후 허용된 수집에서는 실패 본문을 크기 제한·해시와 함께, 응답 헤더는 비밀이 없는 허용 목록만 보존하도록 설계하되 이번에는 수집기를 변경하지 않았다.

## 기존 단계에 반영할 수집·검증 계획

1. **R1/T002 → 현재 T005:** 공급자가 허용하는 상품별 초기 전체 명단 API/내보내기, 파라미터·쿼터·갱신 날짜·자료 출처를 확인한다. 카드 전체 API가 성공해도 상품 포함 관계를 별도로 요구한다. 문서/허용 근거가 없는 임의 API 경로 추측은 하지 않는다.
2. **T005의 작은 검증 사례:** Magical Dribblers150명을 목표 사례로 삼되, 먼저 공식명·해당 회차/출시 시점·종료·지역/플랫폼·공급자 상품 ID를 연결한다. 제공 자료에 전체 초기150명과 원본 출시 카드 ID가 실제 들어 있는지 확인한다. 현재11명과 나머지139명, Standard의 신원·타입은 공급된 관계로만 입증한다. 실패하면 범위를 미확인으로 유지한다.
3. **R2 구조 보강을 동반하는 T005/R5:** 글로벌 카드 카탈로그, 소개 카드 관계, 실제 초기 추첨풀 관계를 구분한다. 향후 모델에 `pool_snapshot`·상품 ID·지역/플랫폼·공식 초기 수·관찰 시각·초기/잔여 구분·카드별 수량/근거/해시·유효 버전을 명시한다. 아직 구현된 테이블이나 수집 결과로 표현하지 않는다.
4. **R5/T006 확대:** 허용 경로에 체크포인트·단일 동시성·백오프·요청 예산을 적용한다. 전체 쪽/cursor·마지막 쪽·총계 안정성·카드 ID별 중복/누락·수량을 검증한다. 카드 이름/타입/이미지 URL은 전체 확인하고 실제 이미지 GET은 표본/전수를 구분한다. 일반 Standard 전체에서 임의로 선발하지 않는다.
5. **R4 공개·R6 운영:** 소개 목록과 검증된 전체 초기 풀의 상태를 각각 표시한다. 실패·빈 응답·삭제 의심으로 정상 풀을 줄이지 않는다. 실제 신규 회차/구성 변화와 실패 복구의 전후 증거가 있어야 지속 갱신 완료로 판정한다.

초기 전체 선수 풀 완료에는 **동일한 상품·회차·지역·버전 연결, 공식 초기 총계, 출처가 명시한 카드별 포함 관계, 전체 페이지와 마지막 응답, 정확한 출시 카드 ID·수량, 누락/중복 해소**가 모두 필요하다. 중복 카드가 허용되는 출처라면 고유ID 수와 수량 합계를 따로 대조하고 근거를 남긴다. 카드 분류·이미지/능력의 미확인은 별도로 표시한다. 감독은 서비스 범위 밖이므로 선수 풀 검증을 상품 전체 구성 완료로 승격하지 않는다.

게임 내 모두 보기를 보조 근거로 사용할 경우 영입 후의 잔여 명단에 주의한다. 초기 미영입 상태임을 확인하거나 완전한 영입 이력과 함께 초기 구성을 복원할 수 있어야 한다. 사용자가 제공하는 완전한 초기 목록은 수동 대조의 대안이며 자동 API 확보 성공이 아니다. 앱의 비공개 인증 API 분석·계정 접근으로 확보하지 않는다.

가장 현실적인 우선순위는 **공급자 허용 전체 명단 API/내보내기 확인 → 한 상품150명 실증 → 공식 대조 후 확장**이다. 사용자 결정이 필요한 부분은 공급자와 API/자료 제공 협의를 진행할지, 완전한 게임 내 초기 목록을 수동 검증 자료로 병행할지다. 연락·가입·유료 계약은 이번에 수행하지 않았고, 성공 경로를 검증하기 전 자동 수집 가능성을 약속하지 않는다.

## 후속 공급망 조사로 확인한 변경 사항

[공급망 조사](DATA_SUPPLY_CHAIN.md)에서 PesLig의 정상 공개 카드 JSON을 실제로 받아 Standard19,018행을 포함한 snapshot을 검사했다. 이 문서의 “상품별 전체 풀 API 미확보”와 전역 카드 조회 경로는 구분한다. 현재도 상품별 Standard 구성 관계와 모든 특수 카드의 회차별 완전성은 미확인이다. 익명 Standard 슬롯안은 후속 판단을 위한 보류 요구이며 구현하지 않았다.

PESDB는 후속 확인한 약관에서 자동 수집/DB 재구축을 금지하고 bulk export/feed를 제공하지 않는다고 명시한다. 앞선 소개 목록 대조는 연구 이력으로 유지하지만 자동 수집 백엔드 후보로 추천하지 않는다. 공개 카드 경로의 성공이 재사용/재배포 허용을 뜻하지 않으며 신규 provider 채택·활성 데이터 변경은 하지 않았다.
