# efsimulator 작업 계획과 이력

최신 사용자 결정에 따라 전체 누적 EFHub DB/API와 공식 KR 현재 판매 사이트 DB를 분리한다. 이번 T020은 전수 점검·계획/인수인계 갱신과 미푸시 자료 이관 준비만 수행한다. 과거 관측·완료 이력은 보존하며 새 구현 완료로 승격하지 않는다.

## 현재 작업과 매 작업 갱신

- 이전 작업: T020 — 전수 최신화 점검·두 계층 계획·Work 인수인계와 오프라인 이관 준비.
- 현재 작업: T021 — 제공 players raw 오프라인 검증 대기/차단. Library 메타 존재, 현재 task materialize 도구 부재. 대상 Work의 packs 수집은 준비 중이며 raw 완료/상세 매핑은 별도 미확인.
- 다음 작업: T010 — 검증된 전체 players/packs 자료의 정식 수집/증분 수입, 예정·이번 구현하지 않음.
- 현재 조건: 전체 누적층은 모든 확보 가능한 EFHub players/packs를 무삭제/개정 보존한다. 사이트층만 최신 공식KR·종료UTC·신선도로 제한한다. EFHub 우선 목표와 지속 공급/권리·이미지·구성 검증 완료는 다르다. 다른 Work raw를 재수집하지 말고 먼저 검증한다. GitHub에는 로컬 최신 파일이 모두 있지 않으며 별도 Sites 초기 페이지/소스는 이관 제외한다.

매 작업 시작 시 Git 상태·이전 결과·이번/다음 작업·선행 조건을 확인한다. FILE_SYNC의 P0→P1→P2로 관련 파일을 검토하되 필요한 파일은 등급과 무관하게 함께 수정한다. 추가 요구는 ID·영향 단계·선행 조건·순서·상태를 기록한다. 파일별 수정/변경불필요/미해결과 근거, 경로 추가/삭제/이름 변경·참조를 같은 작업에서 갱신한다. 검증과 이전/현재/다음 포인터를 맞추며 구현/수집/발행 완료는 실제 근거가 있을 때만 표시한다.

### 목표·입력·순서

입력: 13:41 UTC 사용자 원문, 기존 Git/관리 문서·조사, 공식 KR 새 관측.

1. 공식 페이지의 실제 전체 행·이름·초기 수·종료·확률과 미기재 필드를 재확인한다.
2. 새 범위와 API 선정 조건, 가상 Standard·아카이브·자체 API·배포·시뮬레이터/3D 계획을 작성한다.
3. 이전 기록과 단계 대응표를 보존하고 영향 문서·FILE_SYNC를 갱신한다.
4. 관리 검사·기존 테스트·빌드/공개 생성물 비교와 변경 범위 검증을 마친다.

### 산출물·검증·완료 조건

계획과 기준표가 실제 관측·미확인·미구현을 구분해야 한다. 기존 코드/DB/seed·공개 파일과 과거 근거가 보존되고 필요한 문서 검사와 기존 회귀가 통과하면 문서 작업 완료다. API 미확보는 T009의 미해결 조건이며 이 문서 작업의 구현 완료로 바꾸지 않는다.

### 선행 조건·보류 사항

이번 변경은 문서와 새 조사 기록뿐이다. 구현·푸시·배포·스케줄 활성화는 하지 않는다. 정책 수치는 제안 기본값으로 명시한다.

### 예상 영향 파일

이번 실제 영향 파일은 아래 전수 최신화 검토 표를 따른다. 신규 파일의 경로/역할·연관 파일은 착수 때 확정하고 추가와 동시에 FILE_SYNC에 등록한다.

## T009 — 후보 API 검증과 최종 선정

- 단계: R1
- 상태: 차단
- 이전: T019

### 목표·입력·순서

입력: 최신 공식 기준표, API_SELECTION, 기존 저장 응답·권한/오류 기록.

1. 정상 허용 경로·자동 접근·저장/재배포 조건·쿼터와 비용부터 확인한다. 부족하면 필요한 정확한 공급자 조건을 기록한다.
2. 당시 공식 대상 각각의 회차와 모든 특수 종류의 manifest를 대조한다. 현재 부족한 National/Quaresma/Midfielders 근거를 먼저 보강한다.
3. 선정 시험용 비활성 수집으로 모든 특수 카드의 필드와 이미지 실제 로드→디코딩→허용 저장→재읽기·해시·카드 연결을 검증한다.
4. 안정적인 최신 발견 방식과 실제 공급자 변경 전후·오류/축소 보호·어댑터 계약을 확인하고 모든 필수 게이트가 통과한 뒤 최종 선정한다.

### 산출물·검증·완료 조건

정확 URL/메서드/쿼리·시각/해시·상품별 회차/전체 특수ID·중복/unknown·이미지 전수 결과·권한·갱신 전후·예상 비용과 선정 보고서를 남긴다. 필수 게이트 하나라도 미통과이면 최종 선정/작업 완료 금지다.

### 선행 조건·보류 사항

사용자 실행 승인으로 착수했다. 이미 거부된 요청을 반복·변형하지 않는다. 연락·추가 권한·유료 계약이 필요하면 최소 조치와 근거를 제시한다. 시험 자료는 DB/활성 import가 아니며 T010에서 재사용한다.

### 예상 영향 파일

docs/API_SELECTION.md, 공식 기준표/선정 검증 기록, ROADMAP/WORKPLAN/FILE_SYNC. 새 검증 기록은 추가 즉시 등록한다. 신규 파일의 경로/역할·연관 파일은 착수 때 확정하고 추가와 동시에 FILE_SYNC에 등록한다.

## T021 — 제공 players raw 검증과 packs/관계 입력 확인

- 단계: R1
- 상태: 차단
- 이전: T020
- 다음: T010

### 목표·입력·순서

입력: Library `libfile_cc5085f5c4788191b7c3707a66e0529a`, File Service `file_000000002b808206a31e146aa54fdc3f`, version1,16,801,176bytes(메타 보고). 원문 파일은 수정하지 않는다.

1. 지원 Library prepare_materialize/reference 흐름으로 같은 파일을 materialize한다. 임의 executor 경로 추정/ID를 Sediment 다운로드에 재사용하지 않는다.
2. 바이트 수/SHA256/UTF-8/JSON 배열·항목수·원본ID 문자열/정수토큰·고유/중복/충돌·필수필드/타입/이미지URL 분포를 오프라인 검사한다. 큰 숫자는 lossless 파서/Decimal 또는 원시토큰으로 검증한다.
3. 페이지/수집 시각/total/limit/totalPages/누락/마지막 페이지 근거의 실제 유무를 기록한다. 이미 합쳐진 배열만으로 50840/2119 전수/최신성을 증명하지 않는다. 이미지 URL 존재와 다운로드 성공을 구분하고 이번에는 네트워크 이미지를 읽지 않는다.
4. 대상 Work에서 준비 중인 packs 수집의 기존 출력/체크포인트/계획을 먼저 확인해 이어받는다. 새 채팅·중복 수집을 만들지 않고 준비를 수집 완료로 쓰지 않는다. 팩 raw 완료, 상세/특수 구성·card ID 매핑, 정상 지속 수집/권리는 별도 확인한다. 없는 자료를 생성하거나 재수집부터 시작하지 않는다.

### 산출물·완료 조건·차단

오프라인 원본 검증 보고와 hash/실제 수치·한계, 팩 원본/관계의 상태가 필요하다. 현재 task에는 Library 검색/materialize/업로드 도구가 없어서 내용 검증을 시작할 수 없다. Library 메타 존재는 부모 도구 확인 보고이며 본문 검증은 아니다. 기능 구현/자동화/배포는 이 작업의 산출물이 아니다.
