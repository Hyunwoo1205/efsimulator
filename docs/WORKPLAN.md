# efsimulator 작업 계획과 이력

2026-10-25 13:41 UTC 사용자 원문에 따라 전체 계획을 재정의했다. 단계 번호는 새 ROADMAP의 의미를 따르며 이전 완료를 새 범위 완료로 승격하지 않는다. 이번 산출물은 계획/조사 기록이며 활성 DB·코드·공개파일·설정·운영·스케줄 변경이 아니다.

## 현재 작업과 매 작업 갱신

- 이전 작업: T008 — 공식 기준표 재관측과 전체 계획/관리 문서 정리 완료. 이전 T005의 미완료 이력은 보존.
- 현재 작업: T009 — 실제 검증 후 필수 조건 미충족으로 차단·미완료. 공식G0 통과, 카드 공급자 최종 선정 보류.
- 다음 작업: T010 — API 최종 선정 후 공식 대상 특수 자료 정식 수집, 예정.
- 현재 조건: 대상은 공식KR확률표(새 관측7개, 이후 가변)뿐이다. Standard 실명은 수집하지 않으며 검증된 특수 전체와의 차이는 가상 그룹으로 표현하는 모델이 승인됐다. API 최종 선정은 미충족으로 보류. T009의 독립 비활성 검증을 마쳤고 미통과 조건은 재개 자료 대기다. 활성 데이터·배포/푸시·스케줄은 변경하지 않았다.

매 작업 시작 시 Git 상태·이전 결과·이번/다음 작업·선행 조건을 확인한다. FILE_SYNC의 P0→P1→P2 순서로 영향 파일을 찾되 필요한 파일은 등급과 무관하게 함께 수정한다. 추가 요구는 ID·영향 단계·선행 조건·처리 순서·상태로 등록한다. 파일별 수정/변경불필요/미해결과 근거, 추가/삭제/이름 변경·참조를 같은 작업에서 갱신한다. 검증과 이전/현재/다음 포인터를 맞추고 필수 미해결 파일이 있으면 완료 처리하지 않는다. 예정 작업 착수 때 실제 결과에 따라 상세 순서와 영향 파일을 다시 확정한다.

## T011 — 개별 검증과 중립 DB 표본 제작

- 단계: R2
- 상태: 예정

### 목표·입력·순서

입력: 수집한 대상별 특수 자료, 개별 검증 보고서, ARCHITECTURE 설계안.

1. 각 카드/팩을 원본과 대조한다. 회차·ID·모든 타입·OVR 조건·이미지 저장 재읽기·해시/카드 연결을 검사한다.
2. 완전한 특수 수S, 공식N, 가상A를 검증하고 중립 스키마·원본ID/기존ID 매핑을 확정한다.
3. 필요하면 선정 API 자료로 새 staging DB를 구축한다. 기존 DB/seed/근거는 백업하고 레거시 대응표를 보존한다.
4. 완전한 한 팩을 DB 표본으로 편입해 정규화 후 참조/이미지/수량과 멱등성·실패 복구를 검증한다.

### 산출물·검증·완료 조건

카드별 검증표, S+A=N·unknown/누락0인 표본, 이미지/참조 무결성, 레거시/중립ID 매핑, 재현 가능한 새 DB 표본이 산출물이다. 모든 대상의 원자료 검증과 한 팩의 DB 편입을 별도로 보고한다.

### 선행 조건·보류 사항
