갱신은 R2에서 설계하고 R3에서 구현하며 R4에서 시험운영합니다. R6는 실제 변화와 운영 결과를 검증하는 단계입니다. 구현 이전 단계를 갱신 가동 중으로 표시하지 않습니다.

## 단계별 실행 방향

### R0 개발 관리 기반

1. 단일 상태 주석과 작업 ID로 로드맵·작업 계획을 연결합니다.
2. 관리 파일의 역할·우선순위·연관 관계·갱신 조건을 별도 목록에 등록합니다.
3. 파일 누락·삭제 경로 잔존·잘못된 작업 참조를 검사하고, 각 작업의 영향 파일 검토를 기록합니다.
4. 실제 실행한 관리 검사와 테스트 결과를 기록한 뒤 R1로 전환합니다. 제품 빌드는 완료 조건에 포함하지 않습니다.

### R1 출처·수집 가능성 검증

1. 공식 eFootball과 EFHub 한국어·원문 사이트, 실제 상세 페이지와 정상 요청을 조사합니다.
2. 선수 카드·상품의 식별자, 제공 필드, 이미지 형태, 전체 목록과 추가 페이지를 확인합니다. 감독 개별 조사는 중단하고 일괄 관계 API 미확보에 따른 지원 제외를 유지합니다.
3. 현행 자료와 과거 자료의 확보 범위를 구분하고, 구성 수량·가격·재화·이용 조건의 확인 근거를 수집합니다.
4. 필드별 출처와 미확인 현황, 실제 갱신을 입증할 수 있는 관찰 방법을 기록합니다. 응답 성공만으로 지속 갱신을 확정하지 않습니다.

### R2 데이터·기술 구조 확정

1. 실제 선수·출시 카드·카드 개정본·상품·이미지의 식별과 관계를 표본에 적용합니다. 기존 감독 타입은 비활성 참고이며 활성 수집·검색 대상이 아닙니다.
2. 복수 카드 분류, 구성 대상의 종류·수량, 상품별 가격·재화·옵션·제한·기간·이력과 필드별 출처를 설계합니다.
3. 조사된 규모·검색·갱신 요구를 만족하는 최소 앱·DB·배포용 데이터 구조를 선택합니다.
4. 수집→검증→공개 갱신과 실패 시 기존 데이터 보존을 설계하고, 표본 기반 검증·배포 전환 계획을 확정합니다.

### R3 작은 사례의 전체 흐름 구현

1. 실제 출처로 확인한 작은 카드·상품 사례를 수집하고 관계를 저장합니다. 감독 일괄 관계 API가 없어 모든 상품의 감독 정보는 지원 범위에서 제외합니다.
2. 상품 중심 검색과 상세, 카드 상세·다른 버전·포함 상품 이동을 연결합니다.
3. 종합 능력의 조건·이미지 형태·미확인 값을 실제 화면에 반영하고 필요한 갱신 처리를 구현합니다.
4. 데이터 검증, 재실행의 중복 방지, 관계 일관성, 실패 수집의 공개 데이터 보호를 검사합니다.

### R4 현행 자료 검색 사이트 공개

1. R1에서 정의한 현행 범위의 전체 목록과 구성 수량을 대조하며 수집을 확장합니다.
2. 상품 종류 필터·카드 검색·상품/카드의 관계 이동과 로딩·빈 결과·미확인·오류 화면을 완성합니다.
3. 실제 앱 빌드 결과에 맞게 Cloudflare Pages 구성을 전환하고 공개 주소에서 직접 주소·새로고침·이미지·반응형 탐색을 확인합니다.
4. 갱신을 시험운영하고 실행 결과·실패 대응을 기록합니다. 현행 공개를 과거 전체 자료 수집 완료로 표현하지 않습니다.

### R5 과거 자료·전체 카드 확장

1. 확보 가능한 과거 상품과 전체 카드의 목록·기간·누락 기준을 정리합니다.
2. 실제 출처로 입증되는 다른 버전 관계와 과거 구성·가격·조건·개정 이력을 확장합니다.
3. 페이지 누락·구성 수량·중복 식별·끊어진 관계를 점검하고 전체 수집 범위와 실제 확보 결과를 대조합니다.
4. 과거 자료 탐색을 공개 검색에 반영하고 미확인·확보 불가능 영역을 구분합니다.

### R6 지속 갱신 운영 검증

1. 실제 출처의 신규 자료나 조건 변경을 관찰하고 운영 경로에서 반영된 결과를 확인합니다.
2. 수집 실패·부분 응답·관계/이미지 오류를 검출하고 기존 정상 데이터 보존과 복구를 검증합니다.
3. 확인한 출처 동작에 맞춰 갱신 주기·처리 예산·운영 기록과 다음 점검 기준을 확정합니다.
4. DB·검색 사이트·전체 수집·지속 갱신의 완료 조건을 종합 점검한 뒤 시뮬레이터 별도 기획의 진입 가능 여부를 기록합니다.

## 모든 단계에 적용하는 조건

- **식별:** 내부 고유 ID를 부여하고 외부 ID는 출처·종류·원본 문자열로 보존합니다. 긴 숫자와 선행 0을 유지하며, 이름이나 추측한 숫자 규칙으로 선수를 합치지 않습니다. 실제 선수·출시 카드·개정본을 구분합니다.
- **카드:** 이름·이미지·배경·표시 종합 능력과 적용 조건을 보존합니다. 복수 분류를 허용하고 이미지가 합성본인지 분리 자산인지 기록합니다. 다른 버전은 확인된 출처 관계로 연결합니다.
- **상품·감독:** 카드와 상품의 다대다 관계를 유지합니다. 활성 구성은 카드·기타 상품과 수량을 구분합니다. 감독 항목은 모든 상품에서 서비스 지원 범위 밖이며 실제 포함 여부·수량을 뜻하지 않습니다. 대표 카드 목록을 전체 상품 구성으로 취급하지 않습니다.
- **가격·조건:** 상품 가격과 개봉 옵션별 가격, 재화, 인원수, 이용 제한, 적용 조건, 판매 기간·상태와 변경 이력을 분리합니다. 상품 유형의 예시 가격을 자동 적용하지 않고 미확인을 0·무제한·해당 없음으로 바꾸지 않습니다.
- **근거·갱신:** 필드별 출처 주소·원본 ID·관찰 시각·원문 근거를 남깁니다. 공식·EFHub에서 부족한 부분에 한해 신뢰성과 지속 갱신 근거가 있는 다른 출처를 검토합니다. 실패한 수집으로 정상 데이터를 덮어쓰지 않습니다.
- **제품:** 자연스러운 한국어와 독자 디자인을 사용하고 Managers는 감독으로 표기합니다. 모바일·태블릿·데스크톱을 지원하며 로딩·빈 결과·미확인·오류를 구분합니다. 비코인 상품도 DB·검색 대상입니다.
- **비용:** Pages 무료 구성을 우선합니다. 추가 서버·API가 필요하면 무료 웹/API 호스팅을 검토하고 차선으로 OCI A1 Flex 2 OCPU·12GB ARM64를 평가합니다. 선택 근거·제약·실제 비용 조건을 기록합니다.
- **변경 관리:** 추가 요구사항은 작업 ID·영향 단계·선행 조건·처리 순서·상태와 함께 작업 계획에 반영합니다. 파일 추가·삭제·이름 변경과 영향 파일 검토는 같은 작업에서 최신화 목록에 반영합니다.

시뮬레이터의 추첨 방식·연출·구현은 위 단계의 작업에 포함하지 않습니다. DB와 전체 검색 사이트가 완성되고 갱신이 검증된 뒤, 코인을 사용하는 특수 선수 명단만을 대상으로 별도 계획을 세웁니다.

## 최신 지원 범위와 전체 카드 검증 순서

- 감독 포함 정보를 반복 가능한 일괄 API로 확보하지 못했으므로 모든 상품의 감독 정보와 독립 감독 목록을 지원하지 않습니다. 일부만 수동 연결하지 않으며 실제 상품에 감독이 없다는 뜻이 아닙니다. 원본 연구는 비활성 참고로 보존합니다.
- 일괄 구매·지급형 팩은 DB·검색에 유지하지만 코인 결제여도 미래 개봉 시뮬레이터에서 제외합니다. /packs라는 출처 경로만으로 실제 상품 종류를 판정하지 않습니다.
- 전체 API 접근·페이지네이션·필드 검증은 기존 R1/T002와 R5의 범위입니다. 새 중복 작업을 만들지 않고 R4/T005의 공개 확대 전 선행 검증으로 보강했습니다.
- 실제 감사는 첫 limit100 요청의403에서 중단됐습니다. 과거 정상24개 경로와 현재 UI의 요청 형식 비교만 완료했고 추가 API 요청·쿠키/토큰 취득·우회는 하지 않았습니다. 전체 5만 카드 확보나 이미지 전수 검증 성공이 아닙니다. 검증 범위를 표시한 부분 공개는 허용합니다.
- 카드 수는 출시 카드/원본 ID 수이며 실존 선수 수가 아닙니다. 복수 분류·배경·능력 조건·버전 연결은 목록 필드만으로 완전 확보를 주장하지 않습니다.
