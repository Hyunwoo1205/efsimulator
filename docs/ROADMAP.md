## 현재 실행 순서

1. **T008 — 완료:** 이번 계획과 공식 기준표·API 비교·아카이브/가상 슬롯/배포 방식을 문서로 정리한다. 사용자 계획 확정 전에는 활성 데이터·인프라를 바꾸지 않는다.
2. **T009 — 현재 차단, 조건 확보 후 재개:** 정상 접근·이용조건이 확인된 후보만 공식 대상별로 선정 시험용 비활성 수집과 전수 이미지 저장 시험을 수행한다. 특수 카드 누락 없는 구성, 필수 필드/이미지, 안정 경로/실제 갱신, 저장/재배포 조건이 모두 충족돼야 선정한다.
3. **T010→T011:** 필요한 특수 카드 수집→개별 검증→중립 DB 설계/표본 구축. `공식 초기 수−검증된 특수 수`의 익명 Standard 그룹은 별도 가상 자료로 다룬다. 특수 완전성이 미확인인 팩은 준비 완료로 표시하지 않는다.
4. **T012→T013:** 검토용 URL과 설정 변경 전/후를 제시→사용자 검토→운영 반영 승인→공개 주소 검증. 기존 main은 초기 커밋이므로 전역 빌드 설정을 먼저 바꾸지 않는다.
5. **T014→T015→T016:** 당시 전체 대상 DB 완성→안전한 자동 갱신→자체 API/복구 운영. 종료 팩은 얇은 아카이브에 보존하고 활성 검색/API/캐시와 분리한다.
6. **T017→T018:** 검증된 규칙의 시뮬레이터→가상 Standard/카드 연출→권리·용량·모바일 성능을 검증한3D. Cloudflare 한도를 실측한 뒤 자산 분리/OCI를 비교한다.

## 설계 결정과 차단 요인

- **API:** [API 선정표](API_SELECTION.md)의 필수 조건 모두 통과 전 최종 선정 보류. [T009 실제 검증](sources/API_SELECTION_VALIDATION.md)은 공식G0만 통과하고 나머지 필수 조건이 미완료다. 공식 페이지는 대상/총원/종료/확률 공급원이고 카드 API를 대체하지 않는다.
- **보존/갱신:** [데이터 수명주기](DATA_LIFECYCLE.md)의 얇은 아카이브·마지막 정상 스냅샷·발행/복구·캐시 정리 정책을 추천한다. 영구 삭제를 기본값으로 삼지 않는다.
- **가상 Standard:** 모델 방향은 승인됐으며 신규 DB/시뮬레이터 구현 때 적용한다. 특수 누락·중복·미확인 타입·음수 차이를 가상 카드로 숨기지 않는다.
- **배포/호스팅:** [배포 계획](DEPLOYMENT.md)의 현재 확인값과 제안을 분리한다. 3D가 추가된다는 이유로 OCI 이전을 확정하지 않는다.
- **후속 검토:** 카드 공급 조건/권한 확보와 미기재 게임 규칙, 검토판에 대한 사용자 확인·운영 반영 승인이 각 단계의 별도 조건이다. 지역/플랫폼 추가 선택은 이번 대상 정의의 차단 요인이 아니다.
