# efsimulator 개발 로드맵

최신 사용자 결정은 **전체 누적 DB/API**와 **현재 판매 선수팩을 위한 사이트 DB/배포 스냅샷**을 분리한다. 이전의 “확률표 대상만 수집”은 사이트층에 한정되며, 전체 누적층은 EFHub에서 정상 확보 가능한 모든 players/packs로 확대한다. 기존 엔티티는 삭제하지 않고 변경을 개정 이력으로 보존한다. T023에서 API 독립 소스와 로컬 staging 수입을 준비했다. 공식 현행 projection과 hosted DB/API 운영은 아직 미완료다.

> T024가 이전 두 계층 설명을 구체화/변경한다. raw 전체 보존과 가공 API의 공식 상품 한정을 구분하며 [현재 계약](CATALOG_DATA_CONTRACT.md)을 우선한다.

## 두 계층의 범위

| 구분 | 전체 누적 DB/API | 사이트 DB/배포 스냅샷 |
| --- | --- | --- |
| 모수 | EFHub에서 정상 확보 가능한 모든 선수 카드/선수팩. 출처가 실제 제공하는 범위를 기록 | 공식 한국어 확률표의 최신 정상 목록·종료 UTC·신선도가 확인된 현재 유효 팩과 해당 카드 |
| 보존 | 새 원본 ID 추가, 기존 엔티티 무삭제. 원문/관측/변경 revision 보존 | 활성 대상은 추가·수정·판매 종료/검증 상태에 따라 제외. 전체 누적층과 과거 발행본은 보존 |
| Standard/과거 | 원문에 있으면 보존. 전역 전수 확보 성공 여부는 별도 보고 | 모든 특수 완전성 확인 후 N−S를 익명 Standard 그룹으로 표현. 실명 Standard 상세는 필수 아님 |
| 감독·고정 팩 | players/packs 원문 중첩값은 변형 없이 보존하되 별도 감독 수집/활성 연결은 지원하지 않음 | 감독 일괄 제외. 구매 즉시 일괄 획득 팩은 개봉 시뮬레이터 제외 |
| API | 앱과 별도 Sites Worker + D1. API 소스는 services/catalog-api, 원문은 별도 수입 묶음 | 전체층의 검증된 버전에서 추출. 초기 정적 JSON과 후속 동적 API 구분 |

공식 기준은 https://efootball-web.konami.net/probability_kr.php 이다. 관측 7개를 상수로 쓰지 않는다. 2026-10-25 관측의 Midfielders 종료는 **2026-10-26 10:59:59 KST**로 이번 점검 시점에 이미 지났다. 현재 공식 페이지는 재요청하지 않았으므로 당시 7개를 현재 판매 목록으로 복제하지 않는다. 표 미기재 가격·재화·무료·다회·리셋 규칙은 미확인으로 둔다.

## 현재 실행 순서

1. **T022 이관 완료:** 최신 GitHub work 8ece934와 원격 CI 2개 성공·PR 상태를 확인하고 저장소와 두 raw를 이 Work에 준비했다. 이후 작업도 Git 상태와 원격 변경을 먼저 비교한다. bundle은 선택 백업이다.
2. **T021 완료:** players는 카드 객체·고유 문자열 ID 47,397개, packs는 객체 1,699개와 비어 있지 않은 고유 slug 1,698개로 파일 내부 검사를 마쳤다. 빈 name/slug와 dummy 의심 항목은 원본을 보존하고 격리 검토한다. 페이지 완전성·현재성·팩 관계·이미지 실제 로드는 별도 미검증이며 두 raw를 재수집하지 않는다.
3. **T010 진행/T011 예정:** T022에서 확인한 기존 9팩·79관계의 raw ID 참조를 재사용하고 출처·공식 회차·명단 범위를 검증한다. 팩 raw에는 카드 ID·선수 명단이 없으므로 검증된 팩 회차→카드 ID 관계 근거를 확보한다. 그 실제 필드로 중립 스키마·개정·무삭제 계약을 확정한 뒤 staging 수입과 현행 한 팩 표본으로 이어간다. 모든 과거 팩의 관계 완성을 최초 설계의 새 필수 조건으로 만들지 않는다. T023의 API·schema·수입 준비 결과를 재사용하며 공식 현행 표본과 운영 검증은 별도 완료 조건이다.
4. T012→T013: 실제 앱 dist를 Sites 비공개 검토판으로 배포하고 사용자 검토·운영 반영을 구분한다. GitHub/Sites source SHA·version·URL·라우팅을 기록한다. 이번 T022는 호환성·문서 검토이며 실제 배포·main 병합·추가 push는 수행하지 않는다.
5. T014→T015→T016: 누적 확보 범위와 현행 완전성을 각각 완성/보고하고 두 갱신 파이프라인·자체 API/백업/복구를 검증한다. 누적층에는 물리 삭제를 전파하지 않는다.
6. T017→T018: 검증된 규칙의 시뮬레이터와 익명 Standard 연출, 이후 3D. Sites의 용량/모바일·비용 실측 뒤 R2 자산 분리/OCI를 비교한다.
