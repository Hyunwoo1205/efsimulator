# efsimulator 개발 로드맵

## 현재 위치

최신 사용자 목표는 **현재 상점에서 구입·교환·이용 가능한 선수 관련 상품과 그 구성 카드의 이름·이미지·표시 OVR, 판매 시작/종료·현재 상태를 수집하고 갱신하는 것**입니다. 과거 상품 전체·전역 카드 전수 수집·다른 버전 신규 확보는 핵심 완료 조건에서 제외하고 보류합니다. 기존 데이터·버전 탐색 기능·조사 근거는 보존합니다. 이전 범위의 조사 이력은 현재 필수 요구와 구분합니다.

갱신은 R2에서 설계하고 R3에서 구현하며 R4에서 시험 운영합니다. R6는 실제 현행 변화와 운영 결과로 검증하며 전역5만 카드 감사나 과거 전체 수집에 종속시키지 않습니다. 부분 공개와 합의한 대상 범위의 완료는 구분합니다.

## 단계별 실행 계획

### R0 관리 기반

파일/역할·우선순위·연관 경로·검토 작업을 FILE_SYNC에 등록하고 매 작업의 이전/현재/다음·추가 조건·검증을 WORKPLAN에 남깁니다. 신규/삭제/이름 변경은 같은 작업에서 반영합니다.

### R1 현행 모수와 출처

1. 공식 공개 특수 명단·캠페인·상품 페이지와 검증 가능한 판매처를 조사합니다. 확률표·캠페인·플랫폼 유료판을 별도 모수로 두고 전체상점으로 합산하지 않습니다.
2. 대상 지역/플랫폼과 계정 한정 제공의 공백을 명시합니다. EFHub 역사카탈로그 총계·출처 표시 날짜를 판매 중/판매 시작의 근거로 바꾸지 않습니다.
3. 상품별 원본ID/URL·공식 대응·기간/상태와 소개 카드/전체 초기 풀·필수 카드 필드를 대조합니다. 이름 유사·같은 수량만으로 합치지 않습니다.
4. 정상 공개 경로와 저장 기록을 우선 사용하고 거부 요청 반복·인증/네트워크 우회를 하지 않습니다. 필요한 카드 확보와 전역 카탈로그 전수 수집을 구분합니다.

### R2 구조·최소 정보

1. 기존 문자열 ID·상품↔출시 카드·출처/시각·미확인·변경 이력·실패 보존 구조를 유지합니다. 전역 실인물 DB·다른 버전 완전 연결을 새 필수 작업으로 만들지 않습니다.
2. 현행 판정에 지역/플랫폼·기간의 정밀도/시간대·상태 근거와 확인 시각을 연결합니다. 누적 원본 DB와 현행 노출 뷰를 분리하는 방식을 계획합니다.
3. 이름·이미지·표시 OVR 외 안정ID/타입/상품연결은 동일 카드·구성을 식별하기 위해, 가격/재화/규칙은 추후 정확한 시뮬레이션을 위해 필요합니다. 확인된 최소값부터 보존하며 미확인을0/무료/무제한으로 만들지 않습니다.
4. 유료 인프라 추가 없이 현재 Pages 무료 경로를 우선하고 필요한 경우에만 무료API/DB·보유OCI를 평가합니다.

### R3 기존 흐름 보존

수집→검증→SQLite→화면과 실패 보호의 완료 근거를 유지합니다. 기존 다른 버전 탐색·누적 데이터는 보존하되 그 전수 확장은 보류합니다. 감독은 일괄 관계 API 미확보로 서비스 범위에서 제외하며 실제 상품에 감독이 없다는 뜻이 아닙니다.

### R4 현행 범위 대조와 부분 공개

1. 공식 제한 모수와 EFHub의 상품별 대응 후보/확정·현재 상태·소개/전체 구성을 대조하고 부족한 근거를 기록합니다.
2. 현행 필수 카드 정보와 검색/필터·직접 주소·반응형·미확인/오류 표시를 검증합니다. 검증 전9상품을 판매 중 목록으로 승격하지 않습니다.
3. 기존 Pages/PR 경로의 실제 커밋·CI·공개 동작을 구분합니다. main 운영 반영은 승인 대기 상태를 유지합니다.
4. 현행 자료 갱신을 시험 운영합니다. 전역카드 API 미완료는 연구 이력으로 남기되 현행 공개의 무조건 선행 게이트로 두지 않습니다.

### R5 현행 공백 보강

1. 확정된 지역/플랫폼·공개 모수의 누락/대응 근거, 판매 시작/종료·현재 상태·조건을 보강합니다.
2. 그 상품에 연결되는 카드 ID·이름·이미지·OVR·타입과 확인된 가격/재화/추첨/지명·수량 규칙을 보강합니다. 상품별 소개 목록과 전체 초기 풀을 구분합니다.
3. 전체 구성을 주장하려면 같은 상품/회차의 전체 페이지·원본ID/수량·공식 초기 수·누락/중복을 대조합니다. 익명Standard는 여전히 미도입이므로 미확인을 임의로 채우지 않습니다.
4. 기간 종료는 정상 데이터 삭제 대신 근거 있는 상태/노출 변경으로 다룹니다. 과거 전체·전역 카드·다른 버전 신규 수집은 별도 후속 요청이 있을 때만 다시 계획합니다.

### R6 현행 운영

1. 실제 신규 상품/카드·판매 종료·구성/가격/조건 변경을 출처 전후 관측과 공개 결과로 확인합니다.
2. 실패·빈 응답·급감·이미지/관계 오류에서 정상 원본/공개 데이터 보존과 복구를 검증합니다.
3. 현행 출처 동작에 맞는 주기·예산·기록·다음 점검 기준을 확정합니다. 같은 응답의 반복 조회·fixture/CI 성공만으로 완료 처리하지 않습니다.
4. 현행 DB·검색·갱신의 합의 범위가 검증된 뒤 시뮬레이터를 별도 계획합니다.

## 유지할 조건과 보류 범위

- 일괄 지급 팩은 현행 DB/검색 대상에 남기며 코인 결제여도 미래 개봉 시뮬레이터에서 제외합니다. 미래 대상은 확인된 코인 기반 특수 명단입니다.
- 감독은 모든 상품/독립 목록에서 지원 제외합니다. 익명Standard 슬롯·향후 모션은 조건부 보류이며 실제 카드/ID·확보 수에 섞지 않습니다.
- [전체 명단 조사](sources/FULL_ROSTER_RESEARCH.md)·[공급망 조사](sources/DATA_SUPPLY_CHAIN.md)·실제403 기록은 보존합니다. dt870은 파일 컨테이너이지 원본API 주소가 아니며 사이트 원본 선언과 내부 추출 과정은 구분합니다.
- 원본·출처별 분류·계산/적용 조건·미확인·관측 시각과 정상 자료를 보존합니다. 오래된 데이터를 현행으로 표시하거나 수집 실패로 삭제하지 않습니다.
- 현재 상태·파일 목록·추가 요구·영향 검토를 작업마다 갱신합니다. 유료 구성이나 새로운 지속 권한이 필요하면 구체적 대상과 근거를 제시합니다.
