# efsimulator 개발 로드맵

## 다음 실행 순서

1. **T030 정리:** API 완료 기준과 실제 데이터/배포 근거를 문서·파일 목록·현재 인수인계에 맞추고 같은 작업 브랜치에 검증 결과를 보존한다. main/work/기존 Pages/이관 제외 Site는 자동 변경하지 않는다.
2. **T032 기반 재사용:** 전달한 services/efsimulator-app의 실제 서버·목록/상세·진입 화면과 기존 private API relay를 사용한다. 구현/배포/실조회와 직접 주소는 검증됐지만 hosted 실데이터 브라우저 상호작용 QA는 미수행으로 남긴다.
3. **상품별 준비 구분:** API ready는 simulation_ready가 아니다. 같은 회차의 N·완전 특수S·신선도와 검증한 추첨 규칙을 분리해 기록한다. 복원/비복원·단일/다회·리셋·가격/할인·횟수 제한은 근거가 없는 값을 고정하지 않는다. 미확인 규칙이 필요한 모드만 보류하고 비용 미확인은 비용 표시를 보류한다.
4. **T017 최소 추첨판:** 승인된 설계와 확인한 규칙으로 독립 엔진·익명 Standard·세션·2D 결과를 작게 구현해 검토한다. 애니메이션과 추첨 결과를 분리하고 경계/연속 클릭/버전 변경·접근성을 검증한다.
5. **검토 배포와 운영 결정:** 실제 앱의 비공개 검토 URL과 구체적인 기능/범위를 확인한 뒤 공개 운영·기존 서비스 전환을 별도로 결정한다. private API 공개 여부는 앱 설계의 필수 게이트가 아니다.
6. **T018 3D:** 검증된 엔진과 연출 검토 뒤 모델·권리·모바일 성능·용량/비용·2D fallback을 검증한다. 서버 이전/자산 분리를 근거 없이 먼저 수행하지 않는다.
